\begin{abstract}
Prompts for in-context learning (ICL) can describe a task in addition to, or instead of, demonstrating it through examples. Yet how descriptions work remains largely underexplored. Through the Bayesian view of ICL, we model descriptions as informative priors, characterized by their \emph{specificity} and \emph{reliability}. We adapt the effective sample size (ESS) from Bayesian statistics to quantify a description's predictive value as an equivalent number of demonstrations. Our theoretical results on in-context linear regression tasks show that a reliable description's ESS grows with its specificity and with the task's dimension. However, the ESS falls sharply if the description may be wrong: in a 16-dimensional task with no demonstrations, a one-in-ten chance of being wrong cuts a highly specific description's ESS from 117 to 13.5. We then test whether Transformer networks and pretrained language models, including frontier models, behave like Bayesian predictors in these settings. Meta-trained Transformers come close to the Bayes-optimal ESS when test descriptions are as reliable as training ones. Pretrained language models, however, make too little use of highly specific descriptions when answering without reasoning, and most of them closely match a Bayesian reference only when reasoning is enabled. Taken together, these results extend the Bayesian analysis of ICL from demonstrations to descriptions.
\end{abstract}

\section{Introduction}

Large language models (LLMs) are capable of in-context learning (ICL): given a prompt that specifies a task through a natural-language description, demonstrations, or both, they can predict the output for a new query input \citep{brown2020}. In practice, prompts consist mostly of system instructions, user instructions, agent skill files, and earlier conversation turns, which typically describe the task rather than demonstrate it \citep{mao2025,patsakis2026}. The balance shifts further toward description as LLMs carry out increasingly long-horizon tasks \citep{kwa2025}, for which demonstrations are costly to provide.

Theories of ICL, however, have mostly focused on prompts consisting of demonstrations alone \citep{xie2022,garg2022,akyurek2023}. The few that include descriptions study only particular types, such as a task descriptor giving the mean of the inputs \citep{huangge2025}, a hypothesis class listed in the prompt \citep{lin2025}, or datasets from related tasks that inform the prior \citep{zhu2026}; none offers a systematic treatment of descriptions. We therefore ask: how can we characterize natural-language descriptions in general, so as to understand and analyze them formally? And how well do learners, whether meta-trained Transformers or pretrained language models, use descriptions in practice?

We study these questions through the Bayesian view of ICL, in which a learner infers a latent task, the function that maps each input to its output, from the demonstrations \citep{xie2022}. A description carries information about the task without being a demonstration of it, so the description can be modeled as a prior over tasks. Descriptions differ in how much they say about a task: ``write this report as an accountant'' leaves most of the task open, whereas a step-by-step workflow leaves little. They also differ in whether they are about the right task: an outdated instruction, or an instruction meant for a different task, describes the wrong one. Neither property can be measured directly in a natural-language instruction, so, as a first step, we study a setting in which both are known exactly. We formalize these two properties in $d$-dimensional Gaussian linear regression, a standard controlled setting for ICL \citep{garg2022,panwar2024}, in which a task is a latent regression vector. A description gives a prior mean, the regression vector it points to. We call a description that is about the right task \emph{relevant}. Given a relevant description, the task is Gaussian around its prior mean with standard deviation $\tau$: the more a description says, the smaller $\tau$ and the higher the description's \emph{specificity}. A description is relevant with probability $p$, its \emph{reliability}; otherwise it is \emph{irrelevant}, and its mean is independent of the task (Figure~\ref{fig:overview}).

To compare descriptions with demonstrations, we follow Bayesian work that expresses a prior's information or impact as an equivalent sample size \citep{wiesenfarth2020,reimherr2021,selby2025}, and work that expresses a prompt's value in training data points \citep{lescao2021}. A description's \emph{predictive effective sample size} (ESS) is the number of additional demonstrations that a learner would need, in place of the description, to reach the same expected error. For the Bayes-optimal predictor, ESS gives a description's value under the statistical model; for a trained learner, it gives the value that the learner realizes. To see how well learners use descriptions, we test how close each learner comes to the ESS of a Bayesian predictor given the same information.

Our contributions are as follows:
\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=3pt]
\item \textbf{A model of descriptions as priors.} We characterize a description by two properties that any description has: its specificity and its reliability (Section~\ref{sec:setting}).
\item \textbf{A measure of a description's value in demonstrations.} We adapt effective sample size from Bayesian statistics to prediction error, which can be measured for any learner, including a network or a language model (Section~\ref{sec:setting}).
\item \textbf{The Bayes-optimal value of a description.} When little is known about the task without it, a reliable description with precision $c=\tau^{-2}$ is worth about $c+d+1$ demonstrations before any are seen. Demonstrations lower this value, to about $c$ after many; a description that constrains only part of the task can instead gain value from them (Section~\ref{sec:specificity}). Any fixed positive probability of irrelevance caps the ESS without demonstrations, the zero-shot ESS, at a finite value, however specific the description. Demonstrations can then show whether the description is relevant and raise its ESS above this ceiling (Section~\ref{sec:reliability}, Figure~\ref{fig:ess}b).
\item \textbf{Tests of trained learners against Bayesian predictors.} Meta-trained Transformers approach the Bayes-optimal ESS when test descriptions are as reliable as training ones; without demonstrations, they weight a description by how often descriptions were relevant in training, whatever the test reliability (Section~\ref{sec:networks}). Language models use a precision stated in the prompt mainly with reasoning enabled. Without reasoning, every model tested falls far short of a Bayesian predictor for what the prompt states when the description is highly specific; with reasoning, most closely match its error (Section~\ref{sec:reasoning}).

\section{Problem Setup}\label{sec:setting}

A description carries information about a task that does not come from demonstrations, so we model it as a prior over tasks. Let $Q_0$ be the \emph{baseline prior}, the distribution of tasks when no description is given. A description comes with a prior of its own, $Q_{\mathrm{desc}}$. If the description is about the right task, which we call \emph{relevant}, the task is drawn from $Q_{\mathrm{desc}}$. Otherwise the description is \emph{irrelevant}, and the task is drawn from $Q_0$ whatever the description says. Given a description, the task therefore has the prior
\begin{equation}\label{eq:mixture}
p\,Q_{\mathrm{desc}}+(1-p)\,Q_0,
\end{equation}
where $p$, the description's \emph{reliability}, is the probability that it is relevant. We call the description \emph{reliable} when $p=1$ and \emph{unreliable} when $p<1$. This two-component form is the robust mixture prior that Bayesian clinical trials use to borrow external information that may not apply \citep{schmidli2014}.

A description's \emph{specificity} is how little it leaves unknown about the task when it is relevant. What a prior leaves unknown can be measured by the smallest expected loss that a prediction made from the prior alone attains, its generalized entropy \citep{grunwald2004}. We score predictions by squared error, as is standard for in-context regression \citep{garg2022}. The best prediction from a prior is then the prior's mean, and its expected squared error is the prior's variance (Appendix~\ref{app:specificity}). We therefore measure a description's specificity by the variance of $Q_{\mathrm{desc}}$: the lower the variance, the more specific the description. We study the prior~\eqref{eq:mixture} in Gaussian linear regression.

\paragraph{Tasks and demonstrations.}
A task is a vector $w\in\R^d$, and the baseline prior is $Q_0=\mathcal{N}(0,\tau_0^2I_d)$, where $\tau_0>0$. A prompt contains $n$ demonstrations $D_n=\{(x_i,y_i)\}_{i=1}^n$ and a query input $x$, with
\[
x_i,x\overset{\mathrm{iid}}{\sim}\mathcal{N}(0,I_d),\qquad
y_i=w^\top x_i+\epsilon_i,\quad
\epsilon_i\overset{\mathrm{iid}}{\sim}\mathcal{N}(0,1).
\]
Inputs and observation noise are independent of the task, of its description, and of one another. Numerical illustrations in Sections~\ref{sec:specificity}--\ref{sec:reliability} use $d=16$ and $\tau_0^2=10$; other dimensions and baseline variances give the same pattern (Table~\ref{tab:grid} in Appendix~\ref{app:reliability}).

\paragraph{Descriptions.}
A description supplies a prior mean $m\in\R^d$, and its prior is $Q_{\mathrm{desc}}=\mathcal{N}(m,\tau^2I_d)$ with $0<\tau\leq\tau_0$. Its variance is $\tau^2$ in each direction, so the smaller $\tau$, the more specific the description: a relevant description places the task within about $\tau$ of $m$ in each coordinate. So that learners with and without descriptions face the same tasks, the task must follow $Q_0$ once we average over descriptions. Under a relevant description, $w$ is $m$ plus independent noise of variance $\tau^2$, so $m$ must have variance $\tau_0^2-\tau^2$, the part of the task's variance that the description accounts for. With a latent relevance indicator $Z\sim\mathrm{Bernoulli}(p)$ independent of $m$, the joint model is
\begin{align*}
m&\sim\mathcal{N}(0,(\tau_0^2-\tau^2)I_d),\\
w\mid m,Z=1&\sim\mathcal{N}(m,\tau^2I_d),\\
w\mid m,Z=0&\sim\mathcal{N}(0,\tau_0^2I_d).
\end{align*}
The description is relevant when $Z=1$ and irrelevant when $Z=0$, which gives the prior in~\eqref{eq:mixture}. A description of the wrong task carries no information about this one, so when $Z=0$ its mean is independent of the task. A description of the right task that is only somewhat inaccurate is modeled instead as a relevant description with a larger $\tau$.

To compare a description with demonstrations, we use precision, the inverse of variance, because the precisions of independent Gaussian sources of information add. With unit noise and isotropic inputs, each demonstration adds expected precision $1$ in every direction. We therefore write $c=\tau^{-2}$ for a description's precision and $c_0=\tau_0^{-2}$ for the baseline prior's: a description carries the precision that $c$ demonstrations add. What it is worth in prediction error, its ESS, need not equal $c$, as Sections~\ref{sec:specificity} and~\ref{sec:reliability} show.

\paragraph{Prediction error.}
For a prediction $\hat y$, we measure expected squared error against the noise-free query response:
\begin{equation}\label{eq:regret}
R=\E\big[(\hat y-w^\top x)^2\big].
\end{equation}
We call this quantity \emph{prediction error}, or simply error; it excludes irreducible query noise. The expectation is over tasks, descriptions, demonstrations, and queries. For a fixed learner, $R^{\mathrm{desc}}(n)$ and $R^{\mathrm{base}}(n)$ denote the error with and without a description. As a function of the demonstration count, $R^{\mathrm{base}}$ is the learner's \emph{baseline curve}, its learning curve without the description.

\begin{definition}[Predictive effective sample size]\label{def:ess}
Given $n$ demonstrations, let $n^*$ be the smallest $t\geq0$ satisfying $R^{\mathrm{base}}(t)=R^{\mathrm{desc}}(n)$. When such a $t$ exists, the description's ESS is
\[
\ess_n=n^*-n.
\]
We interpolate the baseline curve between integer counts, so $n^*$ and the ESS need not be integers. When no such $t$ exists, as when the error with the description lies below the learner's whole baseline curve, the ESS is undefined.
\end{definition}

For example, $\ess_n=10$ means that $n$ demonstrations plus the description match the error of $n+10$ demonstrations alone. The ESS without demonstrations, $\ess_0$, is the \emph{zero-shot ESS}.
Definition~\ref{def:ess} follows the prior sample size of \citet{reimherr2021}, who match the mean squared error of an estimate under a prior with that under a baseline prior and additional observations. We match prediction error, which can be measured for any learner, including a network or a language model, whose prior knowledge is only implicit in its parameters. Because ESS is measured on each learner's own baseline curve, a large ESS need not mean a small error, so we also report the language models' absolute error (Table~\ref{tab:error}, Appendix~\ref{app:reasoning-runs}).

\section{The Value of a Reliable Description}\label{sec:specificity}

We first take a reliable description, $p=1$. Its value without demonstrations depends on its specificity and also on the task's dimension. In this section and the next, error and ESS are those of the Bayes-optimal predictor. We state the zero-shot result for a diffuse baseline prior, the limit $\tau_0\to\infty$ with $\tau$ fixed, in which a learner knows little about the task without the description.

\begin{proposition}[Reliable descriptions]\label{prop:reliable}
Let $p=1$.
\begin{enumerate}[label=(\roman*),nosep,leftmargin=*]
\item With $\tau$ fixed and $c=\tau^{-2}$ a positive integer, $\ess_0\to c+d+1$ as $\tau_0\to\infty$.
\item With $\tau$ and $\tau_0$ fixed, $\ess_n\to c-c_0$ as $n\to\infty$.
\end{enumerate}
\end{proposition}

Part (i) follows by comparing the description's error, $d\tau^2=d/c$, with the baseline error after $t$ demonstrations, which in the limit $\tau_0\to\infty$ is $d/(t-d-1)$ for integer $t>d+1$ \citep{muirhead1982}: the two match at $t=c+d+1$ (Appendix~\ref{app:specificity}). If the demonstration inputs gave every direction of the task the same information, the baseline error would be $d/t$ and the description would be worth $c$ demonstrations. Random inputs constrain some directions less than that, so the error is $d/(t-d-1)$, and matching the description takes $d+1$ more demonstrations. At $d=16$ and $\tau_0^2=10$, a reliable description with $\tau=0.1$, so that $c=100$, is worth about $117$ demonstrations before any are seen (Figure~\ref{fig:ess}a).

\paragraph{Demonstrations lower the value of a complete description.}
The descriptions modeled so far are \emph{complete}: they constrain every direction of $w$. By part (ii), after many demonstrations the dimension no longer adds to such a description's value, which tends to $c-c_0$. This limit is the precision that the description adds to the baseline prior, its conventional prior ESS \citep{morita2008} measured relative to that prior. A complete description therefore loses value as demonstrations accumulate: a $c=100$ description is worth $117$ demonstrations before any are seen and $109$ after $100$ (Figure~\ref{fig:ess}b).

\paragraph{Demonstrations can raise the value of a partial description.}
Descriptions often specify only part of a task. A \emph{partial} description constrains only $k<d$ of the $d$ directions and leaves the others at the baseline prior (Proposition~\ref{prop:partial} in Appendix~\ref{app:partial}). Without demonstrations, its error comes almost entirely from the $d-k$ directions it leaves open, and a learner without the description reaches that error after about $k$ demonstrations. After many demonstrations, the description is worth the precision it adds, averaged over all $d$ directions: about $k(c-c_0)/d$ demonstrations, which exceeds $k$ when $c-c_0>d$. At $d=16$ and $\tau_0^2=10$, a $c=100$ partial description with $k=8$ is worth $8.1$ demonstrations before any are seen and $36.2$ after $100$ (Figure~\ref{fig:ess}b).

We now allow the description to be irrelevant with probability $1-p$. The Bayes-optimal predictor must then weigh the two components of the prior~\eqref{eq:mixture} by each one's probability given the demonstrations. Let $\pi_n=P(Z=1\mid m,D_n)$ be the \emph{posterior relevance probability}. The predictor averages the two components' predictions with weights $\pi_n$ and $1-\pi_n$ \citep{hoeting1999}.

\begin{proposition}[Unreliable descriptions]\label{prop:unreliable}
Let $0<p<1$.
\begin{enumerate}[label=(\roman*),nosep,leftmargin=*]
\item Without demonstrations, the error is
\begin{equation}\label{eq:zero}
R^{\mathrm{desc}}(0)=\big[(1-p^2)\,\tau_0^2+p^2\,\tau^2\big]\,d.
\end{equation}
\item With $\tau$ fixed, $\ess_0\to p^2d$ as $\tau_0\to\infty$.
\item With $\tau$ and $\tau_0$ fixed, $\limsup_{n\to\infty}\ess_n\leq p\,(c-c_0)$.
\end{enumerate}
\end{proposition}

\paragraph{Without demonstrations, unreliability imposes an error floor.}
The error in Equation~\eqref{eq:zero} consists of a floor, $(1-p^2)\tau_0^2d$, and $p^2$ times the error $d\tau^2$ of a reliable description. However specific the description, the error stays above the floor, so the zero-shot ESS stays below a finite ceiling: the number of demonstrations at which the baseline error equals the floor. For a diffuse baseline prior the ceiling is $p^2d$, the limit in part (ii), which does not depend on $\tau$. The floor arises because, without demonstrations, nothing shows whether the description is relevant: the posterior relevance probability is still the prior one, $\pi_0=p$, and the Bayes-optimal predictor shrinks the prior mean $m$ by the factor $p$. Figure~\ref{fig:ess}a shows the effect at $p=0.9$. Lowering $\tau$ from $1$ to $0.1$, which raises $c$ from $1$ to $100$, multiplies a reliable description's ESS by more than seven but raises an unreliable one's only from $12.0$ to $13.5$, within $0.1$ of its ceiling.

\paragraph{Demonstrations distinguish low specificity from unreliability.}
By Proposition~\ref{prop:unreliable}, an unreliable description has, without demonstrations, the error of a less specific reliable one. For example, at $d=16$ and $\tau_0^2=10$, a $c=100$ description with $p=0.9$ and a reliable one with $c\approx0.52$ both have ESS about $13.5$. After $100$ demonstrations, their ESS values are $86.6$ and $0.5$. Demonstrations show whether the unreliable description is relevant, and when it is, its high specificity takes effect; the reliable description has low specificity to begin with, so demonstrations cannot raise its value in this way. The rise is not steady (Figure~\ref{fig:ess}b; Appendix~\ref{app:reliability} explains the early dip). The ESS also levels off: in the limit of many demonstrations, it is at most $p(c-c_0)$, which is $p$ times the limit $c-c_0$ of a reliable description (Proposition~\ref{prop:unreliable}(iii)). In simulations, the ESS comes within $0.03$ demonstrations of this bound when $d\geq5$; at $d=1$ it stays as much as $1.3$ below (Table~\ref{tab:gap}, Appendix~\ref{app:reliability}). Table~\ref{tab:summary} in Appendix~\ref{app:proofs} collects the limits of this section and the last.

\section{Experiments}\label{sec:experiments}

Sections~\ref{sec:specificity} and~\ref{sec:reliability} give the Bayes-optimal ESS of a description. We now ask how close two kinds of learner come to a Bayesian predictor's ESS: Transformers meta-trained on our regression model, which must learn a description's specificity and reliability from their training data, and pretrained language models, whose prompts state both and which we test on the scalar case of the model.

\subsection{Meta-Trained Transformers}\label{sec:networks}

Transformers meta-trained on demonstrations can approach Bayes-optimal prediction \citep{garg2022,genewein2025}. We test whether they also attain the Bayes-optimal ESS of a description. Following \citet{garg2022}, we train Transformers, which we call the networks, from scratch on our regression model at $d=5$, the dimension used by \citet{huangge2025}, and $\tau_0^2=10$, with a separate network for each precision $c\in\{1,10\}$ and each reliability $p\in\{1,0.99,0.9\}$. A description token carries the prior mean $m$ but not $\tau$ or $p$, so a network must learn both from its training data (Appendix~\ref{app:networks}).

When training and test reliability match, the networks' ESS without demonstrations is close to the Bayes-optimal ESS on the same prompts (Figure~\ref{fig:networks}a). The largest gap is at $c=10$ and $p=1$: $14.3$ against $16.1$, a Bayes-optimal value close to $c+d+1=16$. When the two reliabilities differ, the networks follow the training one. Without demonstrations, the Bayes-optimal predictor predicts $p\,m^\top x$, weighting the description by the test reliability $p$; a network instead weights it by about the reliability it was trained at, because the description alone gives no sign of how reliable the test descriptions are. Networks trained at $p=0.9$ thus weight descriptions by about $0.88$, the fitted coefficient of their predictions on $m^\top x$, even when every test description is relevant, and reach only $60\%$ of the Bayes-optimal ESS (Figure~\ref{fig:networks}b, Table~\ref{tab:networks}). Appendix~\ref{app:networks} reports the opposite shift.

\subsection{Pretrained Language Models}\label{sec:llm}

Pretrained language models are not trained on our task distribution, so they cannot learn a description's specificity and reliability as the networks do. We therefore state both in the prompt, and ask whether the models use what it states. To isolate the use of a description from the ability to carry out linear regression in context, we use numerical mean estimation. It is the scalar case of our regression model, with fixed input $x=1$; with every input the same, the $d+1$ term of Proposition~\ref{prop:reliable} does not arise, and a Bayesian predictor's ESS is close to $c$. Using a stated precision requires weighting the description and the demonstrations by their precisions. Reasoning may help a model carry out this computation, so we compare models with reasoning enabled and disabled.

\paragraph{Task and prompts.}
Each task has a hidden mean $w\sim\mathcal{N}(500,100^2)$, and its demonstrations are drawn from $\mathcal{N}(w,\sigma^2)$ with $\sigma=60$, which the prompt states. These values keep every number shown to three digits, which language models predict best \citep{gruver2023,requeima2024}. A description gives a prior mean $m$ and a standard deviation $\tau$: “Its mean was drawn from a normal distribution with mean 510 and standard deviation 30.” We generate $m$ as in Section~\ref{sec:setting}, so the task lies within about $\tau$ of it. Each demonstration now adds precision $\sigma^{-2}$, so the description carries the precision of $c=\sigma^2/\tau^2$ demonstrations; stated standard deviations of $60$, $30$, and $10$ give $c=1$, $4$, and $36$, from a description with the precision of one demonstration to one with the precision of $36$. Because a more precise description also has a more accurate prior mean, a model could do well with $c=36$ descriptions without using the stated precision. To separate the two, we also give the $c=36$ descriptions with a stated precision of $c=4$ (Appendix~\ref{app:prompts}).

\paragraph{Models.}
We give the same $200$ tasks to five models whose reasoning can be enabled and disabled: gpt-oss-20b \citep{openai2025}, Qwen3.5 9B \citep{qwen35}, Gemma~4 31B \citep{gemma4}, GPT-6 Sol \citep{openai2026sol}, and Claude Opus~4.6 \citep{anthropic2026opus}. Claude Haiku~5.5 \citep{anthropic2026haiku}, whose reasoning could not be disabled in our setup, appears only with reasoning.

\paragraph{Bayesian reference.}
We compare each model with a \emph{Bayesian reference}, the Bayesian predictor for the statistical model that the prompt states. With a description, the reference predicts the precision-weighted mean $(cm+n\bar y)/(c+n)$, where $\bar y$ is the sample mean of the demonstrations, up to the rounding and the finite range of the numbers shown. Without one, the prompt says only that the mean is “unknown”, because a stated distribution would itself be a description. The reference then takes a uniform prior over the integers $100$ to $999$, the range of every number shown. This prior is not the normal distribution that generates the tasks, so agreement with the reference shows that a model follows what the prompt states, not that its error is the lowest possible on these tasks.

\paragraph{Evaluation.}
Models rarely answer with a number when the prompt has neither a description nor demonstrations, so we compute ESS at $n=1$, $2$, and $4$ against each model's own baseline curve and report the median of the three values, the \emph{median ESS}. The reference's median ESS is $1.0$, $3.5$, and $34.6$ at $c=1$, $4$, and $36$. These values differ slightly from $c$ because of the finite task sample and the interpolation of the baseline curve. ESS is least stable where a baseline curve is nearly flat, because a small difference in error then spans many demonstrations, and it is censored when the error with the description lies outside the range of the baseline curve. Across four ways of estimating the curve, the median ESS of the models without reasoning moves by at most $1.4$ demonstrations (Appendix~\ref{app:ess-est}).

\paragraph{Language models use a stated precision mainly with reasoning enabled.}\label{sec:once}\label{sec:reasoning}
Without reasoning, all five models fall far short of the reference at $c=36$: median ESS ranges from $2.0$ to $10.3$, against $34.6$ for the reference (Figure~\ref{fig:llm}b), and root-mean-square error from $13.6$ to $39.1$, against $9.3$ to $9.5$ (Table~\ref{tab:error}). With reasoning enabled, four of the six models predict nearly as the reference does. Opus~4.6, GPT-6 Sol, and Gemma~4 31B attain its ESS at both precisions (Figure~\ref{fig:llm}a,b), and at $c=36$ their error is within $0.3$ of the reference's. Qwen3.5 9B matches its error, to within $0.1$ in root-mean-square error at every demonstration count (Table~\ref{tab:error}), but its ESS at $c=36$ is undefined, because its own baseline curve stops falling after about $32$ demonstrations; the square in Figure~\ref{fig:llm}b measures it on the reference's baseline curve instead. Appendix~\ref{app:reasoning-runs} reports the other two models, Haiku~5.5 and gpt-oss-20b, and a seventh, Olmo~3 7B Think, which always reasons and falls well short of the reference.

The models that match the reference use the stated precision itself: they do not merely average the demonstrations better, or benefit from the more accurate prior mean of a precise description. When we lower only the stated precision of the $c=36$ descriptions, to $c=4$, the reference's ESS falls to $13.7$, and that of Opus~4.6, GPT-6 Sol, and Gemma~4 31B falls to between $11$ and $14$ (Table~\ref{tab:reason}). The comparison between the two modes has one caveat. For the open-weight models, the runs with and without reasoning also differ in serving software, in decoding, in how the prediction is read out, or in retry policy, so for these models we compare the configurations we evaluated and do not isolate reasoning. The two runs of Opus~4.6 differ only in the reasoning setting, and they show the same gap (Appendix~\ref{app:reasoning-runs}).

\paragraph{Stated reliability.}\label{sec:llm-stated}
Section~\ref{sec:reliability} shows that demonstrations can reveal whether an unreliable description is relevant. To test whether language models use demonstrations in this way, we add a sentence to the $c=36$ description: “There is a 10\% chance that this statement is wrong, in which case the mean was instead drawn uniformly at random from the whole numbers 100 to 999.” Each task is presented once with its relevant description and once with an irrelevant one, and we average the two errors with weights $0.9$ and $0.1$. For cost reasons, we ran this experiment on three of the models, GPT-6 Sol, Opus~4.6, and Haiku~5.5 (Appendix~\ref{app:llm-reliability}). The stated chance cuts the reference's ESS from $34.6$ to $5.0$ (Figure~\ref{fig:llm}c). Most of what remains comes from using the demonstrations to judge whether the description is relevant: a predictor that keeps the chance of irrelevance at the stated $10\%$, whatever the demonstrations show, has an ESS of only $0.3$. With reasoning, GPT-6 Sol and Opus~4.6 reach $4.8$ and $5.0$, and Haiku~5.5 reaches $3.2$; without reasoning, GPT-6 Sol and Opus~4.6 reach only $0.9$ and $1.0$ (Table~\ref{tab:matched}).
\paragraph{Descriptions in words.}
The descriptions above state a distribution, whereas descriptions in practice usually state constraints in words. We therefore ran two of these three models, GPT-6 Sol and Haiku~5.5, on a second task, message sorting (Appendix~\ref{app:semantic}). A hidden rule, one of $60$, sorts messages into two folders by two of their six properties, and the description is a note that narrows down the rule. A note leaves the rules compatible with it equally likely, so it is more specific the fewer rules it leaves. A broad note, such as ``whether it concerns travel is one of the two properties the policy uses'', leaves $20$; a specific note, which names both properties and the value one must take, leaves $2$. Models give a probability for each message's folder, scored by squared error, and the reference is the exact Bayesian predictor over the $60$ rules. With reasoning, a specific note at $n=2$ is worth $9.5$ and $9.9$ demonstrations to the two models, against $11.4$ for the reference, and their ESS is within $2$ demonstrations of the reference's in every other case but one (Table~\ref{tab:semantic}). The exception is GPT-6 Sol's specific note at $n=4$, $26.1$ against $14.8$, where its own baseline curve flattens. Appendix~\ref{app:semantic} also reports notes that may be wrong.


\section{Related Work}

\paragraph{Theories of ICL.}
Prior work studies ICL as Bayesian inference over latent tasks \citep{xie2022,panwar2024}, as a learning algorithm implemented in a forward pass \citep{akyurek2023,vonoswald2023}, and as meta-learning across tasks \citep{garg2022,muller2022}. Agreement of meta-trained predictors with Bayesian ones can depend on training-task diversity and on the function class \citep{raventos2023,panwar2024}. \citet{lin2024} study a prior that mixes task groups, a mixture like the one an unreliable description induces here. In these accounts, the prior over tasks comes from pretraining or meta-training. The works closest to ours put prior information in the prompt, but each analyzes one particular kind \citep{huangge2025,lin2025,zhu2026}. We differ in characterizing a description by two properties that any description has, its specificity and its reliability, and in measuring its value in demonstrations.

\paragraph{Prior effective sample size.}
Prior ESS expresses the information or impact of a prior as an equivalent sample size, with different definitions matching different statistical quantities \citep{morita2008,neuenschwander2020}. Our measure is closest to those based on expected loss \citep{reimherr2021,wiesenfarth2020}. \citet{selby2025} compare priors elicited from language models with data-based predictors; their measure is the number of observations needed to match predictive loss. We apply loss matching to task descriptions, at each demonstration count and against each learner's own baseline curve. Related measures express a prompt or an instruction in training examples: \citet{lescao2021} measure a prompt's average data advantage in fine-tuning, and \citet{cook2026} find that, in fine-tuning, an instruction can replace up to $100$ examples. We measure descriptions used in context.

\paragraph{Descriptions and evidence in language models.}
\citet{gupta2025} give language models an explicitly stated coin bias together with observed flips, evaluate their predictions against Bayesian predictors, and find that in the models' predictions the observed flips outweigh the stated bias. Our language-model experiments differ in stating the precision and the reliability of a description separately, measuring its value in demonstrations against each model's own baseline curve, and comparing reasoning enabled and disabled. Concurrent work studies how reasoning and code execution affect language models' approximation of Bayesian posteriors \citep{filbry2026}; we vary only reasoning, with code execution disabled. Appendix~\ref{app:related} discusses further connections.

\section{Discussion}\label{sec:discussion}

We asked how descriptions can be characterized and how well learners use them in practice. For the first question, we treated a description as a prior with a specificity and a reliability, and we measured it by its predictive ESS. A reliable description can replace many demonstrations; unreliability imposes a finite ESS ceiling before demonstrations are observed; and demonstrations can then raise a description's ESS by supplying evidence about its relevance. For the second, meta-trained Transformers approach the Bayes-optimal ESS and, without demonstrations, weight a description by how often descriptions in their training data were relevant. Language models make too little use of a precise description without reasoning; with reasoning, most use a stated precision as the Bayesian reference does.

Our controlled analysis suggests why a description can substitute for many examples \citep{honda2025} or have limited influence \citep{webson2022,gupta2025,gloaguen2026}. A description has little influence when it says little about the task, when it may be about the wrong task, when the demonstrations already supply what it says, or when the learner does not use it. The Bayes-optimal ESS reflects the first three, and a learner's shortfall from it reflects the fourth. For prompt design, the results suggest that an instruction that may be wrong should come with demonstrations, which let the learner check it: without them, its value is capped however specific it is (Section~\ref{sec:reliability}). A prompt that warns that an instruction may be wrong should also state the alternative: when ours said only that the mean was otherwise ``unknown'', the models we tested made little use of the demonstrations to check the description (Appendix~\ref{app:llm-reliability}). More broadly, treating a description as a prior extends the Bayesian analysis of ICL from demonstrations to descriptions.

\paragraph{Limitations and future work.}
We model a relevant description as a single Gaussian prior around one prior mean: a description that points to one task and is more or less specific about it. Future work could model other forms of description, such as one that names several candidate tasks, with a mixture of Gaussians, which can approximate a wide class of priors \citep{dalal1983}. Most of our language-model prompts state a description's precision and reliability explicitly, as numbers, so that every prediction can be compared with a Bayesian reference. In practice, these properties are implicit: a more specific instruction is typically a longer one that says more about the task. The message-sorting task, whose descriptions state no numbers, is a first step toward such instructions. Wording already matters in our numerical task: when the prompt gave the same prior as ``about $m$, give or take $\tau$'', Haiku~5.5, the one model we tested this way, mostly repeated the prior mean even with reasoning (Appendix~\ref{app:wording-reasoning}). How well models infer these properties from the wording of realistic instructions is the next question, and predictive ESS applies to it directly, since it requires only a learner's errors with and without the description. Our language-model experiments also use small synthetic tasks, and two of them cover only two or three models.

\section*{Impact Statement}
This work studies how learners combine task descriptions with demonstrations. Its measurement framework can inform prompt evaluation and design when descriptions might be about the wrong task or leave much of it open. The experiments use synthetic tasks; their results do not establish dependable instruction following in consequential applications.

\subsection{Reliable Descriptions}\label{app:specificity}

\paragraph{Notation and error.}
As in Section~\ref{sec:setting}, $c_0=1/\tau_0^2$ is the baseline prior precision and $c=1/\tau^2$ is the description's. Let $X_n\in\R^{n\times d}$ contain the demonstration inputs as rows, and set $W_n=X_n^\top X_n$. For a prior precision $\kappa>0$, define
\[
R^{\kappa}(n)=\E\operatorname{tr}(\kappa I_d+W_n)^{-1}.
\]
Thus $R^{\mathrm{base}}=R^{c_0}$ and, for a reliable description, $R^{\mathrm{desc}}=R^c$. Here and throughout, error is the expected squared prediction error against the noise-free query response $w^\top x$. Both identities hold because the Bayes-optimal prediction is the posterior mean. Given the prompt and a query $x$, its expected squared error is $x^\top\Sigma x$, where $\Sigma=(\kappa I_d+W_n)^{-1}$ is the posterior covariance; averaging over the independent query, with $\E[xx^\top]=I_d$, gives $\operatorname{tr}\Sigma$.

Throughout the proofs, $d$ is a positive integer, $0<\tau\le\tau_0$, so that $c\ge c_0$, $s=1-\tau^2/\tau_0^2\in[0,1)$, and $p\in[0,1]$. Specificity is measured by the relevant component's variance $\tau^2$; $s$ is the share of the baseline variance that the description removes. Reliability $p$ is the prior probability of relevance. Noninteger demonstration counts refer to linear interpolation between the errors at adjacent integers. We call the count $n^*$ of Definition~\ref{def:ess} the \emph{crossing}.

\paragraph{Wishart identities.}
We use three standard properties of $W_n$.
\begin{enumerate}[label=(W\arabic*),leftmargin=*]
    \item If $n<d$, then $W_n$ has rank $n$ almost surely. Consequently, $(\kappa I_d+W_n)^{-1}$ has $d-n$ eigenvalues equal to $1/\kappa$.
    \item If $n\ge d$ and $e$ is a fixed unit vector, then $(e^\top W_n^{-1}e)^{-1}\sim\chi^2_{n-d+1}$ \citep[Theorem~3.2.12]{muirhead1982}. Hence
    \[
    \E\operatorname{tr}W_n^{-1}=\frac{d}{n-d-1}\quad(n\ge d+2),
    \]
    whereas this expectation is infinite for $n=d$ and $n=d+1$.
    \item For fixed $d$, as $n\to\infty$,
    \[
    \E\operatorname{tr}W_n^{-2}=\frac{d}{n^2}+O(n^{-3}),
    \qquad
    \E\operatorname{tr}W_n^{-3}=O(n^{-3})
    \]
    \citep{vonrosen1988}.
\end{enumerate}
The Sherman--Morrison identity implies that an additional demonstration strictly decreases the expected trace of the posterior covariance. Thus $R^\kappa(n)$ is strictly decreasing, and (W2) implies that it tends to zero. Its linear interpolation is therefore continuous and strictly decreasing. In the correctly specified joint model, conditioning on the description cannot increase expected posterior variance, so $R^{\mathrm{desc}}(n)\le R^{\mathrm{base}}(n)$ and the Bayes-optimal ESS is nonnegative.

\paragraph{Diffuse baseline prior.}
Several results use the baseline error measured in units of the baseline variance $\tau_0^2$. For every integer $n$,
\[
\frac{R^{c_0}(n)}{\tau_0^2}
=\E\operatorname{tr}(I_d+\tau_0^2W_n)^{-1}
\longrightarrow(d-n)^+
\qquad\text{as }\tau_0\to\infty.
\]
Indeed, an eigenvalue $1/(1+\tau_0^2\lambda)$ is bounded by one and converges to the indicator of $\lambda=0$, so dominated convergence and the almost-sure rank of $W_n$ apply. The same limit holds at every real $t\ge0$ by interpolation. Each finite-$\tau_0$ curve is strictly decreasing, and monotone functions that converge pointwise to a continuous limit converge locally uniformly. Hence, if an error level $\ell(\tau_0)$ satisfies $\ell(\tau_0)/\tau_0^2\to\lambda$ with $0<\lambda<d$, the count at which the baseline error equals $\ell(\tau_0)$ converges to $d-\lambda$, the only point where $(d-t)^+=\lambda$.

\begin{proof}[Proof of Proposition~\ref{prop:reliable}]
\emph{(i) No demonstrations.}
A reliable description without demonstrations has error $R^{\mathrm{desc}}(0)=d\tau^2$, the trace of its prior covariance. For fixed $\tau$, this error, $d/c$, does not depend on $\tau_0$. As $\tau_0\to\infty$, monotone convergence, (W1), and (W2) give
\[
R^{c_0}(n)\longrightarrow
\begin{cases}
+\infty,&n\le d+1,\\[2pt]
\displaystyle\frac{d}{n-d-1},&n\ge d+2.
\end{cases}
\]
The finite part of this limiting curve equals $d/c$ at the integer $n=c+d+1$. For every $t<c+d+1$ the limiting error exceeds $d/c$, and for every $t>c+d+1$ it is smaller, so the crossing of the interpolated finite-$\tau_0$ error converges to $c+d+1$. The baseline curve is interpolated linearly between integer counts, so the limit is exactly $c+d+1$ only for integer $c$, and the proposition is stated for that case.

\emph{(ii) Many demonstrations.}
This is the case $k=d$ of Proposition~\ref{prop:partial}(ii), proved in Appendix~\ref{app:partial}.
\end{proof}

At a finite $\tau_0$, the limit in part (i) is a good guide when the description is much more precise than the baseline prior, $c\gg c_0$. At $d=16$ and $\tau_0^2=10$, a $c=100$ description is worth $116.9$ demonstrations, against $c+d+1=117$, and a $c=1$ description is worth $15.6$, against $18$ (Table~\ref{tab:grid} gives other dimensions and baseline variances).

\paragraph{A fixed share of the baseline variance.}
The limit $\tau_0\to\infty$ can also be taken with the description removing a fixed share $s=1-\tau^2/\tau_0^2$ of the baseline variance, so that $\tau$ grows in proportion to $\tau_0$. A learner with $t<d$ demonstrations and no description knows nothing about $d-t$ directions of $w$, and as $\tau_0\to\infty$ its error is dominated by what those directions contribute, $(d-t)\tau_0^2$. The description alone leaves an error of $d\tau^2=(1-s)d\tau_0^2$, which this learner matches at $t=sd$: a description that removes a share of the uncertainty is worth that share of $d$ demonstrations.

\begin{proposition}[Fixed share]\label{prop:share}
Let $p=1$ and let the share $s\in[0,1)$ be fixed. Then $\ess_0\geq sd$, and $\ess_0\to sd$ as $\tau_0\to\infty$.
\end{proposition}

\begin{proof}
By (W1), $R^{c_0}(n)\ge(d-n)\tau_0^2$ for $n<d$; the inequality also holds trivially for $n\ge d$. Linear interpolation preserves this bound, so
\[
R^{\mathrm{base}}(t)\ge(d-t)\tau_0^2\qquad(t\ge0).
\]
The description error is $d\tau^2=(1-s)d\tau_0^2$. For $t<sd$, the right-hand side above exceeds it. The crossing $n^*$ of Definition~\ref{def:ess} therefore satisfies $n^*\ge sd$, so $\ess_0\ge sd$. In units of $\tau_0^2$, the description error is $(1-s)d$. For $s\in(0,1)$, this level lies strictly between $0$ and $d$, so by the diffuse-baseline limit the crossing converges to $d-(1-s)d=sd$. For $s=0$, the description is uninformative and $\ess_0=0$ for every $\tau_0$.
\end{proof}

\subsection{Unreliable Descriptions}\label{app:reliability}

The posterior relevance probability is $\pi_n=P(Z=1\mid m,D_n)$, whereas $p$ remains the prior relevance probability. Conditional on $Z=1$, the posterior parameters are
\[
\Sigma_1=(cI_d+W_n)^{-1},
\qquad
\mu_1=\Sigma_1(c m+X_n^\top y_{1:n}).
\]
Conditional on $Z=0$, the description's mean $m$ is independent of $w$, and
\[
\Sigma_0=(c_0I_d+W_n)^{-1},
\qquad
\mu_0=\Sigma_0X_n^\top y_{1:n}.
\]
Because $m$ has the same distribution under both relevance states, its density cancels from the posterior odds, and the posterior relevance probability follows from the two Gaussian marginal likelihoods of the demonstrations,
\begin{align*}
L_1&=\mathcal N\!\left(y_{1:n};X_nm,I_n+\tau^2X_nX_n^\top\right),\\
L_0&=\mathcal N\!\left(y_{1:n};0,I_n+\tau_0^2X_nX_n^\top\right),\\
\pi_n&=\frac{pL_1}{pL_1+(1-p)L_0}.
\end{align*}
The query input does not enter this update because it is independent of $(Z,m,D_n)$. Without demonstrations, both marginal likelihoods equal one, so $\pi_0=p$. The Bayes-optimal prediction is the posterior mean, $\big(\pi_n\mu_1+(1-\pi_n)\mu_0\big)^\top x$ \citep{hoeting1999}.

\begin{proof}[Proof of Proposition~\ref{prop:unreliable}]
\emph{(i) No demonstrations.}
At $n=0$, $\mu_1=m$, $\mu_0=0$, and $\pi_0=p$, so the prediction is $p\,m^\top x$. For each coordinate,
\[
\operatorname{Var}(w_i)=\tau_0^2,\qquad
\operatorname{Var}(m_i)=\tau_0^2-\tau^2=s\tau_0^2,\qquad
\operatorname{Cov}(w_i,m_i)=ps\tau_0^2.
\]
It follows that
\[
\E(w_i-pm_i)^2
=\tau_0^2-2p^2s\tau_0^2+p^2s\tau_0^2
=(1-p^2s)\tau_0^2
=(1-p^2)\tau_0^2+p^2\tau^2.
\]
Since $\E[xx^\top]=I_d$, the prediction error is $\E\|w-pm\|^2$. Summing over coordinates proves Equation~\eqref{eq:zero}. Because $p\,m$ is the mean of the mixture prior~\eqref{eq:mixture} given $m$, this error is the trace of that prior's covariance, averaged over $m$.

\emph{(ii) The ceiling and its limit.}
Since $R^{\mathrm{base}}(0)=d\tau_0^2$ and $s<1$, Equation~\eqref{eq:zero} gives, for every $\tau>0$,
\[
R^{\mathrm{desc}}(0)
=(1-p^2s)R^{\mathrm{base}}(0)
>(1-p^2)R^{\mathrm{base}}(0).
\]
The error on the left decreases to the right-hand side as $\tau\to0$, equivalently $s\to1$. The interpolated baseline error is continuous, strictly decreasing, and tends to zero. Let $n_p^{\sharp}$ be the count at which the baseline error equals $(1-p^2)\tau_0^2d$, the ceiling of the proposition; it is unique and finite. The crossing $n^*$ is strictly below $n_p^{\sharp}$ and converges to it as $\tau\to0$. Finally, the error level that defines $n_p^{\sharp}$ is $(1-p^2)d$ in units of $\tau_0^2$, which lies strictly between $0$ and $d$. By the diffuse-baseline limit of Appendix~\ref{app:specificity}, $n_p^{\sharp}\to d-(1-p^2)d=p^2d$ as $\tau_0\to\infty$. With $\tau$ fixed instead of $s$, $s\to1$ as $\tau_0\to\infty$, and the same limit gives $\ess_0\to p^2d$.

For comparison, a predictor that also observes $Z$ predicts $m^\top x$ when $Z=1$ and $0$ when $Z=0$, with zero-shot error
\[
p\,d\tau^2+(1-p)\,d\tau_0^2=(1-ps)\,d\tau_0^2.
\]
As $\tau\to0$ this error tends to $(1-p)d\tau_0^2$, so by the same limit its zero-shot ESS ceiling approaches $pd$ as $\tau_0\to\infty$, against $p^2d$ for the Bayes-optimal predictor, which does not observe $Z$. The difference, $p(1-p)d$, is the cost of not knowing whether the description is relevant.

\emph{(iii) Many demonstrations.}
The predictor that observes $Z$ also bounds the ESS after many demonstrations. Given $Z$, it is the Bayes-optimal predictor for the corresponding component, so its error with $n$ demonstrations is $pR^{c}(n)+(1-p)R^{c_0}(n)$. It predicts with the posterior mean given $(Z,m,D_n)$, and the Bayes-optimal predictor with the posterior mean given $(m,D_n)$ alone. Conditioning on less cannot lower the expected squared error, so
\[
R^{\mathrm{desc}}(n)\ge pR^{c}(n)+(1-p)R^{c_0}(n).
\]
The expansion in the proof of Proposition~\ref{prop:partial}(ii), applied with $\Lambda=cI_d$ and with $\Lambda=c_0I_d$, gives for every fixed real $t\ge0$
\[
R^{\mathrm{base}}(n+t)-\big[pR^{c}(n)+(1-p)R^{c_0}(n)\big]
=\frac{d}{n^2}\Big[p\,(c-c_0)-t+O(n^{-1})\Big].
\]
Fix $t>p(c-c_0)$. For all large $n$ the right-hand side is negative, so $R^{\mathrm{base}}(n+t)<R^{\mathrm{desc}}(n)$. The crossing $n^*$ exists, because $R^{\mathrm{desc}}(n)\le R^{\mathrm{base}}(n)$ and the interpolated baseline error is continuous and tends to zero (Appendix~\ref{app:specificity}); since that error is strictly decreasing, $n^*<n+t$, that is, $\ess_n<t$. Since $t>p(c-c_0)$ is arbitrary, $\limsup_{n\to\infty}\ess_n\le p(c-c_0)$: even a predictor that knew whether the description was relevant would gain the added precision $c-c_0$ only with probability $p$.
\end{proof}

Part (i) also connects an unreliable description to Proposition~\ref{prop:share}. Equation~\eqref{eq:zero} equals $(1-p^2s)\,d\tau_0^2$, the zero-shot error of a reliable description that removes the share $p^2s$ of the baseline variance. The proof of Proposition~\ref{prop:share} uses the description only through this error, so it applies with $p^2s$ in place of $s$: $\ess_0\ge p^2sd$, and $\ess_0\to p^2sd$ as $\tau_0\to\infty$ with $s$ fixed.

Simulations indicate that the bound is nearly attained when the dimension is $5$ or more and is looser in the scalar case. The ESS can stay below it in the limit because the Bayes-optimal predictor remains unsure whether the description is relevant, which the predictor that observes $Z$ is not: its error exceeds that predictor's by the between-component term $V_n$ of the posterior variance, and by the expansion above an error difference of $V_n$ costs $n^2V_n/d$ demonstrations. Table~\ref{tab:gap} gives Monte Carlo estimates of the limit of this gap: it is below $10^{-4}$ demonstrations at $d=16$ and grows as the dimension falls, because with fewer directions the task itself shows less clearly whether the description is relevant. The bound concerns the limit, not each finite $n$: at $d=16$, $\tau_0^2=10$, $c=100$, and $p=0.9$, where the bound is $89.91$, the ESS is $86.6$ at $n=100$, $90.6$ at $n=400$, and $90.1$ at $n=3{,}000$, so it approaches the limit from above.

\subsection{Partial Descriptions}\label{app:partial}

Descriptions often specify only part of a task. In our model, a reliable description may then constrain only $k$ of the $d$ directions of $w$; Proposition~\ref{prop:partial} gives its ESS, and the case $k=d$ is the complete description of Section~\ref{sec:specificity}. Formally, in the $k$ constrained coordinates, $m_i\sim\mathcal N(0,\tau_0^2-\tau^2)$ and $w_i\mid m\sim\mathcal N(m_i,\tau^2)$, as in Section~\ref{sec:setting}; in the remaining $d-k$ coordinates, $m_i=0$ and $w_i\sim\mathcal N(0,\tau_0^2)$. The prior precision given the description is $c=1/\tau^2$ in the constrained directions and $c_0=1/\tau_0^2$ elsewhere. Write
\[
\Lambda=\operatorname{diag}(cI_k,c_0I_{d-k}).
\]
The prediction error is $\E\operatorname{tr}(\Lambda+W_n)^{-1}$. Rotational invariance of $W_n$ means that the result depends on the number of constrained directions, not on their orientation.

\begin{proposition}[ESS of a partial description]\label{prop:partial}
Let $p=1$ and let $0\le k\le d$ be an integer.
\begin{enumerate}[nosep]
    \item[(i)] If $k<d$, then $\ess_0\to k$ as $\tau_0\to\infty$ with $\tau$ fixed.
    \item[(ii)] For fixed $d$, $\tau_0$, and $\tau$, as $n\to\infty$,
    \[
    \ess_n\longrightarrow\frac{k}{d}(c-c_0)
    =\frac{k}{d}\,sc.
    \]
    In particular, a complete description has $\ess_n\to c-c_0$.
\end{enumerate}
\end{proposition}

As the baseline prior becomes diffuse with $\tau$ fixed, the unconstrained directions dominate the zero-shot error, and ESS approaches the number of constrained directions, $k$. With even one unconstrained direction, the error with the description stays of order $\tau_0^2$, which a learner without the description matches after about $k$ demonstrations; only a complete description brings the error down to order $\tau^2$, which takes $c+d+1$ demonstrations to match. After many demonstrations, ESS instead approaches the added precision averaged across all $d$ directions. When $c-c_0>d$, this large-sample ESS, $k(c-c_0)/d$, exceeds the diffuse-prior zero-shot ESS $k$, so for a diffuse enough baseline prior the description is worth more after many demonstrations than before any. Table~\ref{tab:partial} illustrates this: at $c=100$, a description of half of the $d=16$ directions has ESS $8.1$ without demonstrations and $36.2$ with $100$ demonstrations.

\begin{proof}[Proof of Proposition~\ref{prop:partial}]
\emph{(i) No demonstrations.}
The description error is $\operatorname{tr}\Lambda^{-1}=(d-k)\tau_0^2+k\tau^2$. In units of $\tau_0^2$, it is
\[
d-k+\frac{k\tau^2}{\tau_0^2}\longrightarrow d-k
\qquad\text{as }\tau_0\to\infty.
\]
If $0<k<d$, this limit lies strictly between $0$ and $d$, so by the diffuse-baseline limit of Appendix~\ref{app:specificity} the crossing converges to $d-(d-k)=k$. If $k=0$, the description leaves the prior unchanged and its ESS is zero.

\emph{(ii) Many demonstrations.}
Applying the resolvent identity twice gives
\[
(\Lambda+W_n)^{-1}
=W_n^{-1}-W_n^{-1}\Lambda W_n^{-1}
+W_n^{-1}\Lambda W_n^{-1}\Lambda(\Lambda+W_n)^{-1}.
\]
Rotational invariance implies
\[
\E W_n^{-2}=\frac{\E\operatorname{tr}W_n^{-2}}{d}I_d.
\]
The expected trace of the middle term is therefore
$\operatorname{tr}(\Lambda)/n^2+O(n^{-3})$ by (W3). To bound the remainder, use $|\operatorname{tr}(MB)|\le\|M\|_{\mathrm{op}}\operatorname{tr}B$ for $B\succeq0$, together with $(\Lambda+W_n)^{-1}\preceq W_n^{-1}$. Its absolute trace is at most
\[
\|\Lambda\|_{\mathrm{op}}^2\|W_n^{-1}\|_{\mathrm{op}}^2\operatorname{tr}W_n^{-1}
\le d\|\Lambda\|_{\mathrm{op}}^2\operatorname{tr}W_n^{-3},
\]
whose expectation is $O(n^{-3})$. Consequently,
\[
\E\operatorname{tr}(\Lambda+W_n)^{-1}
=\frac{d}{n-d-1}-\frac{\operatorname{tr}\Lambda}{n^2}+O(n^{-3}).
\]
The baseline error is the case $\Lambda=c_0I_d$; if $k=0$ or $c=c_0$, the two errors coincide and $\ess_n=0$. Otherwise, fix an integer $T>k(c-c_0)/d$. Since $d/(n+t-d-1)=d/(n-d-1)-dt/n^2+O(n^{-3})$, uniformly over integers $0\le t\le T$,
\[
R^{\mathrm{base}}(n+t)-\E\operatorname{tr}(\Lambda+W_n)^{-1}
=\frac{d}{n^2}\left[\frac{\operatorname{tr}\Lambda-dc_0}{d}-t+O(n^{-1})\right].
\]
Linear interpolation gives the same expansion for real $t\in[0,T]$. The baseline error is strictly decreasing, so for large $n$ the left-hand side vanishes at exactly one $t$ in this range, which is $\ess_n$. Hence
\[
\ess_n=\frac{\operatorname{tr}\Lambda-dc_0}{d}+O(n^{-1})
\longrightarrow\frac{k(c-c_0)}{d}.
\]
One more demonstration and one more unit of prior precision in every direction both lower the error by $d/n^2$ to leading order, which is why a description's large-sample ESS is the precision it adds, averaged across directions.
\end{proof}

\section{Transformer Experiments}\label{app:networks}

\paragraph{Setup.}
Following \citet{garg2022}, we train from scratch on the model of Section~\ref{sec:setting}, with $\tau_0^2=10$ and $d=5$, the dimension used by \citet{huangge2025}. A prompt contains an optional description token carrying $m$, up to $20$ demonstration tokens, and a query token \citep{huangge2025}. The description token does not state $\tau$ or $p$; a network must learn these properties across training tasks. Half the prompts omit the description; a network's predictions on such prompts give its own baseline curve. The main networks are trained separately for $c\in\{1,10\}$ and $p\in\{1,0.99,0.9\}$; further networks, described later in this section, cover $c=0.2$ and $2$, $d=10$, and a partial description. The two main precisions are a factor of ten apart, as are the two nonzero probabilities of irrelevance, $1-p=0.01$ and $0.1$, so that a few networks span a wide range. We do not train at $c=100$, where the ESS would exceed the $20$ demonstrations a network sees.


\paragraph{Matched training and test reliability.}
When training and test reliability match, the networks come close to the Bayes-optimal ESS (Figure~\ref{fig:networks}a; Table~\ref{tab:networks}). The largest gap is at $c=10$ and $p=1$, where networks reach a mean ESS of $14.3$ against $16.1$ on the same prompts (Table~\ref{tab:networks} gives $15.9$, from a larger sample); in every other configuration, they are within $0.3$ of the Bayes-optimal ESS.

\paragraph{Reliability shifts.}
Each network learns how much to weight a description from how often descriptions were relevant in its training data, but descriptions at test time may be more or less reliable than that. We therefore evaluate each network at test reliabilities that differ from its training reliability, and compare it with two Bayesian predictors \citep{raventos2023}: one that uses the training reliability $p_{\mathrm{train}}$, and one that uses the test reliability $p_{\mathrm{test}}$ and is therefore Bayes-optimal. Because a Bayesian predictor with reliability $p$ predicts $p\,m^\top x$ at $n=0$, we summarize a network's predictions by the \emph{fitted description weight} $q$, the coefficient from regressing them on $m^\top x$.

For $c=10$, networks trained at $p=0.9$ keep description weights near $0.9$, as the $p_{\mathrm{train}}$ predictor does, even when every test description is relevant (Table~\ref{tab:networks}), and so fall short of the Bayes-optimal ESS (Figure~\ref{fig:networks}b). The opposite shift, from reliable descriptions in training to unreliable ones at test time, costs little without demonstrations (Figure~\ref{fig:networks}b). The two shifts differ because the Bayes-optimal error differs in size. When one description in ten is irrelevant, that error is already large, and a weight of $1$ instead of $0.9$ adds only about $5\%$ to it. When every description is relevant, the error is small, and a weight of $0.9$ instead of $1$ roughly doubles it. With six or more demonstrations, however, the description raises the error of networks trained at $p=1$ when they are tested at $p=0.9$, whereas networks trained at $p=0.99$ are not harmed (see \emph{Reliability shift after demonstrations are observed} below).

\paragraph{Evaluation.}
We evaluate each network on $20{,}000$ fresh prompts. The networks share these evaluation prompts, so standard deviations across training seeds exclude prompt-sampling variation. At $d = 5$, we evaluate the baseline curve at every integer from $0$ to $20$, except for $c = 0.2$ and $c = 2$, which use counts from $0$ to $15$. We do not train networks at $c=100$, the precision used in Sections~\ref{sec:specificity}--\ref{sec:reliability}: at $d=5$, its Bayes-optimal ESS, about $106$, lies far beyond the $20$ demonstrations over which a network's baseline curve is measured. We compute ESS at the first crossing of this curve with the prediction error obtained using the description, as in Definition~\ref{def:ess}. Table~\ref{tab:networks} reports results at $n = 0$, including test reliabilities that differ from the training reliability.

\paragraph{Architecture.}
The Transformer has $12$ layers, $8$ attention heads, and width $256$, matching the model size of \citet{garg2022}. Layers use pre-normalization, GELU activations, feed-forward width $1{,}024$, and no dropout. At $d = 5$, the model has $9.5$ million parameters.

\paragraph{Tokens.}
The description token carries $m$, each demonstration token carries an input and its label, and the prediction is read from the query token. Two indicator coordinates distinguish token types, and the model uses no positional encoding. When a description is absent, its token is masked out of attention. Labels and description means are divided by $\tau_0$.

\paragraph{Optimization.}
Following \citet{zhu2026}, the model predicts a mean and a log variance for the query label and minimizes log loss. The optimal predicted mean is the posterior mean, which also minimizes squared error, and we evaluate the predicted mean using the loss in Equation~\eqref{eq:regret}. We train with Adam, using the PyTorch defaults $\beta_1 = 0.9$ and $\beta_2 = 0.999$ and stability constant $10^{-8}$, at a constant learning rate of $10^{-4}$ with no weight decay, for $40{,}000$ steps of $1{,}024$ newly sampled prompts and no curriculum. Gradients are clipped to norm $1$, and training uses bf16 autocast. The demonstration count is sampled uniformly from $0$ to $20$, except for the $c = 0.2$ and $c = 2$ experiments, which use $0$ to $15$, and the $d = 10$ experiments, which use $0$ to $40$. We train three seeds for $c = 10$, for $d = 10$, and for the partial description; two for $c = 1$; and one each for $c = 0.2$ and $c = 2$. A $d = 5$ network takes approximately $80$ minutes to train on one NVIDIA L4 GPU, and a $d = 10$ network takes approximately $2.8$ hours. Training all $25$ networks takes approximately $38$ GPU-hours.

Without a description, every $d = 5$ network's error is within $0.21$ of the Bayes-optimal error of approximately $50$ at $n = 0$, and within $0.32$ on average over its training demonstration counts. At $d = 10$, the gap is at most $0.50$ at $n=0$, where the Bayes-optimal error is approximately $100$, and $0.41$ on average over the training demonstration counts. With a description at $c = 10$, $p = 1$, and $n = 0$, network error ranges from $0.67$ to $0.71$, compared with $0.49$ for the Bayes-optimal predictor. The networks therefore remove $98.6\%$ of the baseline error, compared with $99.0\%$ for the Bayes-optimal predictor.

\paragraph{Additional specificity levels.}
Four additional networks cover $c = 0.2$ and $c = 2$, each at $p = 1$ and $p = 0.9$. Their zero-shot ESS is within $0.03$ of the Bayes-optimal value on the same prompts. Network and Bayes-optimal ESS are $2.64$ and $2.66$ at $c=0.2$ and $p=1$, $2.16$ and $2.15$ at $c=0.2$ and $p=0.9$, $7.32$ and $7.35$ at $c=2$ and $p=1$, and $4.38$ and $4.37$ at $c=2$ and $p=0.9$.

\paragraph{Higher dimension and partial descriptions.}
At $d = 10$, we train three seeds with $c = 10$ and $p=1$, and extend training and evaluation to $40$ demonstrations so that the baseline curve reaches the ESS crossing. Network ESS is $17.8$, compared with a Bayes-optimal value of $20.8$ and the limiting expression $c + d + 1 = 21$. As at $d = 5$ with $c=10$ and $p=1$, the networks capture most of the description's predictive value but fall short of the Bayes-optimal ESS.

We also train networks with a partial description, as defined in Appendix~\ref{app:partial}. The description token contains $m$ in the first $k = 3$ of the $d = 5$ coordinates and zeros elsewhere; the remaining task coordinates follow the baseline prior. For this description, at $c = 10$ and $p = 1$, mean ESS across three seeds increases from $3.27$ at $n = 0$ to $5.55$ at $n = 10$. The corresponding Bayes-optimal values are $3.22$ and $5.64$. This increase agrees with the behavior described by Proposition~\ref{prop:partial}.

\paragraph{ESS with demonstrations.}
Figure~\ref{fig:networks-ess-n} evaluates each network at its training reliability. For $c = 1$, network ESS remains within $0.6$ of the Bayes-optimal value at every demonstration count whose crossing lies within the evaluation grid. For $c = 10$, the largest shortfalls are $2.4$, $2.9$, and $1.4$ demonstrations at $p = 1$, $0.99$, and $0.9$, respectively; the largest excess is $0.3$. Demonstrations can raise the ESS of an unreliable description (Section~\ref{sec:reliability}): for the three $c = 10$ networks trained at $p = 0.9$, ESS rises from $4.66$ at $n=0$ to between $4.77$ and $4.83$ at $n = 5$, and the Bayes-optimal ESS on the same prompts rises from $4.63$ to $5.20$.

\paragraph{Reliability shift after demonstrations are observed.}
For $c = 10$, networks trained at $p = 1$ and $p = 0.99$ both have fitted description weights near one at $n = 0$. With demonstrations, their responses to a shift in test reliability differ. At test reliability $p = 0.9$, the description reduces error for networks trained at $p = 0.99$ at every evaluated $n$, as it does for the Bayes-optimal predictor under the test distribution. For networks trained at $p = 1$, the description instead increases error from six demonstrations onward in every seed. The excess error ranges from $0.77$ to $1.06$ at $n = 6$ and peaks between $2.74$ and $2.94$ at $n = 9$. A Bayesian predictor that assumes relevance ($p = 1$) also first has higher error than the baseline predictor at $n = 6$, with excess error $1.12$ there and $2.96$ at $n = 9$; this predictor returns the relevant component's prediction, $\mu_1^\top x$, whatever the demonstrations show. These networks behave as if every description were relevant.

\section{Additional Language-Model Results and Evaluation Details}\label{app:llm}

To measure behavior without reasoning more precisely and on more models, we run six open-weight models without reasoning on $2{,}000$ tasks; we refer to these experiments as the \emph{$2{,}000$-task run}. The models are gpt-oss-20b, Qwen3.5 9B, and Gemma~4 31B, which also appear in Section~\ref{sec:llm}, together with Phi-4 (14B; \citealp{abdin2024}), OLMo~2 32B Instruct \citep{walsh2025}, and Gemma~4 12B. The main numerical experiments in Section~\ref{sec:llm} use the first $200$ of these tasks. The message-sorting experiment uses a separate set of $200$ tasks, described in Appendix~\ref{app:semantic}. Appendices~\ref{app:prompts}--\ref{app:wording} and the complete tables at the end use the $2{,}000$-task run; the other subsections use the $200$-task runs of Section~\ref{sec:llm}.

Table~\ref{tab:llm} reports median ESS over $n \in \{1,2,4\}$, with uncertainty intervals. Figure~\ref{fig:curves} shows the underlying learning curves. Tables~\ref{tab:llm-worth} and~\ref{tab:llm-worth-written} report ESS at every evaluated demonstration count; Table~\ref{tab:sensitivity} compares interpolation methods; and Table~\ref{tab:llm-full} reports description weights for the models with a distribution readout.

For the numerical experiments, the \emph{Bayesian reference} combines the probabilistic statements in the prompt with an assumed baseline prior when the prompt does not specify one. It is optimal under that assumed model, but need not minimize error under the actual task distribution when the two differ. We therefore distinguish this reference from the correctly specified Bayesian predictor in the theory. The message-sorting experiment specifies a finite task distribution and uses its exact Bayesian predictor.

In the numerical task, $c=\sigma^2/\tau^2$ is the prior precision expressed in units of one demonstration. In one condition, the precision used to generate a description differs from the one stated in the prompt: descriptions generated at $c=36$ are stated at $c=4$ (Section~\ref{sec:llm}); there we name both. Similarly, a stated reliability supplies a prior relevance probability to the model; it need not equal the proportion of relevant descriptions in the evaluation sample.

\subsection{Prompts, Tasks, and Answer Extraction}\label{app:prompts}

\paragraph{Model inclusion.}
We retain a model only if its numeric response rate, defined below for the readout we use, is at least three quarters overall and, averaged over $n=1$, $2$, and $4$ and both noise levels ($\sigma=30$ and $60$; see \emph{Task generation}), at least one half without a description, since those replies determine the baseline curve used for median ESS. This criterion excludes MiniCPM5~2B \citep{minicpm5}, OLMo~2 7B Instruct, and OLMo~2 13B Instruct, whose replies begin with a number in $62\%$, $20\%$, and $10\%$ of cases, respectively. These models often begin with explanations such as ``To predict\ldots'' or ``Given\ldots'' despite the numeric-only instruction.

The $2{,}000$-task run uses Hugging Face Transformers at each model's native precision, with checkpoints \path{openai/gpt-oss-20b}, \path{microsoft/phi-4}, \path{allenai/OLMo-2-0325-32B-Instruct}, \path{Qwen/Qwen3.5-9B}, \path{google/gemma-4-12B-it}, and \path{google/gemma-4-31B-it}. Tasks are generated with a fixed random seed, so every model sees the same tasks. Reasoning is disabled where the chat template supports this option. gpt-oss-20b writes its reasoning in a separate channel before its answer; we start generation directly in the answer channel.

\paragraph{Distribution and written readouts.}
For gpt-oss-20b, Phi-4, and OLMo~2 32B without reasoning, the prediction is the mean of the first-token distribution, renormalized over the $900$ three-digit number tokens. We call this the \emph{distribution readout}. It is possible for these three models because their tokenizers encode each number from $100$ to $999$ as a single token; the other models' tokenizers split numbers into digits. Other models, and all reasoning runs, use the number in the final answer, called the \emph{written readout}. We also evaluate written readouts for the three distribution-readout models as a robustness check (Table~\ref{tab:llm} for gpt-oss-20b, and Table~\ref{tab:paraphrase}). OLMo~2 32B assigns $41\%$ of first-token probability to numbers without a description at $n = 1$, and $75\%$ at $n = 2$. Its distribution readout at $n = 1$ therefore summarizes a minority of the first-token probability mass.

\paragraph{Prompt.}
The following text is supplied as the user turn in the model's chat template:
\begin{quote}\scriptsize\ttfamily\raggedright
The numbers below are drawn from a normal distribution with standard deviation 60.\\
Its mean was drawn from a normal distribution with mean 510 and standard deviation 30.\\[3pt]
548\\
431\\[3pt]
Predict the next number. Reply with the number only.
\end{quote}

Without a description, the second sentence is ``Its mean is unknown.'' To state unreliability, a third sentence is added. In the mixed design of Section~\ref{sec:llm-stated} (Appendix~\ref{app:llm-reliability}), it reads ``There is a 10\% chance that this statement is wrong, in which case the mean was instead drawn uniformly at random from the whole numbers 100 to 999.'' With no demonstrations, the final question is ``Predict the first number.''

\paragraph{Task generation.}
A relevant description's prior mean is sampled conditional on the task so that the joint distribution satisfies $m \sim \mathcal{N}(500,100^2-\tau^2)$ and $w\mid m \sim \mathcal{N}(m,\tau^2)$. Demonstrations are rounded to integers. Language models predict short unsigned numbers best \citep{gruver2023,requeima2024}, so we keep every number to three digits: a task is redrawn if a displayed number or prior mean falls outside $100$ to $999$, which occurs for less than $1\%$ of tasks. The $2{,}000$-task run also includes $\sigma = 30$ conditions. Both standard deviations stated in the prompt are then halved, preserving $c \in \{1,4,36\}$. The qualitative pattern is unchanged (Table~\ref{tab:llm-worth}).

\paragraph{Numeric response rates.}
For the distribution readout, the numeric response rate is the probability mass assigned to number tokens at the first position. For the written readout, it is the fraction of replies containing a three-digit number. Tables~\ref{tab:paraphrase}, \ref{tab:llm-worth}, \ref{tab:llm-worth-written}, and~\ref{tab:llm-full} report this quantity as ``number''. Tables~\ref{tab:paraphrase} and~\ref{tab:llm-full} italicize cells whose rate is below three quarters.

\paragraph{Written-readout implementation and checks.}
The written readout extracts the number in the last \verb|\boxed{}| expression in the final answer, if present. Otherwise, it takes the last number with three digits before an optional decimal part, retaining the decimals. A digit group after a thousands separator, as in $14{,}945$, does not count as a qualifying number. In the $2{,}000$-task run, decoding is greedy with a limit of eight new tokens, so the reply is the number itself; for these replies, the readout takes the first qualifying number and keeps only its integer part. Replies without a qualifying number are excluded from both error curves and weight regressions; the reported response rates identify the extent of this exclusion.

For gpt-oss-20b, written-readout weights differ from distribution-readout weights by at most $0.21$ across all conditions and demonstration counts. For $c = 1$, $4$, and $36$, written-readout median ESS is $0.2$, $2.0$, and $3.7$, compared with $0.9$, $2.0$, and $2.8$ from the distribution readout. A single greedy response is a noisier summary than the distribution mean. Phi-4 produces a number in only $58\%$ of written replies across all conditions, so Table~\ref{tab:llm} reports only its distribution readout. In the wording experiment of Appendix~\ref{app:wording}, however, its numeric response rate exceeds three quarters for the original wording, so Table~\ref{tab:paraphrase} includes its written replies. OLMo~2 32B produces a number in only $5\%$, $36\%$, and $48\%$ of written replies without a description at $n = 1$, $2$, and $4$, respectively, with $\sigma = 60$; we therefore do not report its written-readout ESS. Its written-readout weights for the three relevant descriptions at $n = 1$ are $0.83$, $0.81$, and $0.83$, compared with distribution-readout weights of $0.72$, $0.70$, and $0.70$.

\subsection{ESS Estimation and the Bayesian Reference}\label{app:ess-est}

\paragraph{Measurement.}
We apply Definition~\ref{def:ess} to squared error against the hidden mean. In the $2{,}000$-task run, the baseline curve is evaluated at $n = 1$, $2$, $4$, $\ldots$, $64$. Because this grid doubles $n$, we interpolate squared error linearly in $\log n$, which is less biased here than interpolation in $n$ (see \emph{Sensitivity to interpolation} below). The ESS at $n$ is the crossing $n^*$, the first interpolated demonstration count whose baseline error matches the error with the description, minus $n$. For a decreasing baseline curve, a negative ESS indicates higher error with the description than without it at the same demonstration count. For the Bayes-optimal predictor under the correctly specified model, conditioning on a description cannot increase expected error, so its ESS is nonnegative.

If the error with the description lies below the entire baseline curve, which ends at $t_{\max}=64$, we report $\ess_n > t_{\max}-n$. Because the curve starts at one demonstration, we use the marker $\ess_n \leq 1-n$ when one demonstration alone already gives lower error. These markers record censoring at the evaluation boundaries; they do not define an extrapolated matching count or an exact ESS when the crossing does not exist. Median ESS uses $n = 1$, $2$, and $4$. We exclude $n = 0$ because models rarely return a number without a description or demonstrations. At large $n$, ESS is strongly affected by slow baseline learning and excessive weight on the $c = 1$ and $c = 4$ descriptions. At $\sigma = 60$ and $n = 64$, model root-mean-square error without a description ranges from $9$ to $20$, compared with $7.5$ for the reference. A learner with a flatter baseline curve can assign a larger ESS to the same error reduction. Description-weight estimates complement ESS because they do not use that curve. We obtain them by regressing predictions on $m$, $\bar y$, and an intercept: the coefficient on $m$ is the \emph{fitted description weight}, and the reference weight is $c/(c+n)$, which ranges from $0.2$ to $0.97$ over the conditions we evaluate.

Bootstrap replicates resample tasks jointly for the curves with and without the description and recompute the complete ESS statistic. The intervals therefore measure variation across tasks; they do not include interpolation bias, quantified below. We use $500$ replicates with a fixed seed and the same resampled tasks for every model.

\paragraph{The reference's baseline prior and its exact ESS.}
Because every input is the same, the $d+1$ term of Section~\ref{sec:specificity}, which arises from random inputs, does not arise here: in the idealized continuous Gaussian model with a flat baseline prior, a correctly specified description has exact ESS $c$, its conventional prior ESS \citep{neuenschwander2020}. The Bayesian reference takes ``unknown'' to mean uniform over $100$ to $999$. Without a description, its prediction is therefore approximately the sample mean, with negligible boundary truncation for the evaluated prompts. For a relevant Gaussian description with correctly stated precision, the idealized continuous model with a flat baseline prior gives exact ESS $c$. Integer rounding, finite-range truncation, and the task-rejection rule are not part of that exact identity; we compute the reported reference values on the same generated tasks as the models. When a chance of being wrong is stated, the reference uses it as the prior probability of irrelevance and computes the posterior relevance probability from the demonstrations. Otherwise, it treats the description as relevant.

Applying the empirical ESS procedure to the reference on the $2{,}000$-task run gives $1.3$, $4.4$, and $36$ for $c = 1$, $4$, and $36$ at $\sigma = 60$, and $1.2$, $4.7$, and $43$ at $\sigma = 30$. Interpolation in $\log n$ induces an upward bias, while finite-task sampling can shift the estimate in either direction. We use the same estimator for the reference and the models. On the $200$ tasks of Section~\ref{sec:llm}, the grid additionally includes $n = 40$ and $48$ near the $c = 36$ crossing, and the reference values are $1.0$, $3.5$, and $34.6$. In the open-alternative design of Appendix~\ref{app:llm-reliability}, in which every description is relevant and the prompt says only that the mean is otherwise unknown, the reference's median ESS varies more across task samples: on $20{,}000$ tasks it is $7.3$ at a stated $50\%$ and $23.4$ at $10\%$, compared with $5.8$ and $22$ on all $2{,}000$ tasks and $5.7$ and $27.5$ on the first $200$. Each model is compared with the reference on the same tasks.

The actual task prior, $\mathcal{N}(500,100^2)$, is not stated in the prompt. A reference using that prior would have baseline precision equivalent to $0.36$ demonstrations at $\sigma = 60$ and $0.09$ at $\sigma = 30$. At $\sigma = 60$, the corresponding idealized continuous Gaussian model would give a relevant description exact ESS $c-0.36$, namely $0.64$, $3.64$, and $35.64$. This is the scalar analogue of $c-c_0$ in Section~\ref{sec:specificity}. We use the Bayesian reference because the models are not given the actual task prior. This distinction matters under misspecification: unlike the correctly specified Bayesian predictor in Sections~\ref{sec:specificity}--\ref{sec:reliability}, a reference that incorrectly assumes an irrelevant description to be relevant can have negative ESS, indicating increased prediction error \citep{reimherr2021}.

\paragraph{Sensitivity to interpolation.}
The grid of the $2{,}000$-task run doubles $n$, so interpolation can affect ESS. On the reference's idealized errors, $\sigma^2/n$ without a description and $\sigma^2/(c+n)$ with one, interpolation in $\log n$ overestimates ESS by $0.2$, $0.3$, and $1.8$ for $c = 1$, $4$, and $36$. Linear interpolation in $n$ gives overestimates of $0.3$, $0.6$, and $4.1$.

For the models without reasoning, every crossing is unique, because every baseline curve decreases over the counts where crossings occur. Among the twelve baseline curves across the two noise levels, the only increase is Phi-4's at $\sigma = 60$, whose root-mean-square error rises slightly from $20.3$ at $n = 32$ to $20.4$ at $n = 64$. Table~\ref{tab:sensitivity} compares four estimators: interpolation in $\log n$; linear interpolation in $n$; a least-squares non-increasing fit using the pool-adjacent-violators algorithm; and a relative-least-squares fit of $A/(n+n_0)+B$ to the baseline errors. This last form is a Bayesian learning curve plus an error floor and recovers exact ESS when fit to the reference's idealized errors.

Across these choices, no model's median ESS changes by more than $1.4$ demonstrations. For the $c = 36$ description, no model exceeds $8.1$, while the reference ranges from $35$ to $38$. Differences become larger at higher demonstration counts, where a flat learning curve turns a small error difference into a large change in ESS. For example, gpt-oss-20b at $n = 8$ and $c = 36$ has ESS $17$ under the primary log-$n$ estimator (Table~\ref{tab:llm-worth}), but $9.2$ under the fitted curve.

\subsection{Irrelevant Descriptions and Wording}\label{app:wording}

Apart from the stated-reliability experiments of Section~\ref{sec:llm-stated}, the experiments in the main text keep every description relevant, and all of them state its precision in one wording. This section relaxes each of these choices in the $2{,}000$-task run.

\paragraph{Irrelevant descriptions.}
An irrelevant description states a prior mean drawn independently of the task, from the same distribution as relevant prior means, with the same stated precision. At $c = 36$, these descriptions have negative ESS for every model and for the Bayesian reference, which treats them as relevant. The models assign less weight to the description and consequently incur lower error in this condition: at $n = 4$, their root-mean-square errors range from $35$ to $64$, compared with $124$ for the reference.

\paragraph{Wording without reasoning.}
Descriptions in practice express uncertainty in many ways. To test whether the results depend on the original wording, we repeat the three relevant-description conditions and the no-description baseline at $n = 1$, $2$, and $4$ using three alternative description sentences: ``Its mean is about $m$, give or take $\tau$.'', ``Mean: $m \pm \tau$'', and ``An earlier estimate put its mean at $m$, with a standard error of $\tau$.'' Table~\ref{tab:paraphrase} uses the tasks of the $2{,}000$-task run and written readouts.

Wording substantially changes the weight assigned to the description. For Gemma~4 12B with $c = 1$ and $n = 1$, this weight is $0.34$ under the original wording and $1.00$ under each alternative. For gpt-oss-20b, it ranges from $0.17$ to $0.67$. Nevertheless, none of the tested wordings yields the reference's sensitivity to prior precision: across models and wordings, the weight difference between $c = 36$ and $c = 1$ is at most $0.25$ at $n = 1$ and $0.44$ at $n = 4$, compared with reference differences of $0.47$ and $0.70$. The informal descriptions do not uniquely specify a probability distribution, so this comparison changes how explicitly the prompt specifies the prior, not only its wording.

\subsection{Reasoning Settings and Inference Details}\label{app:reasoning-runs}

\paragraph{Comparisons between modes.}
The labels ``with reasoning'' and ``without reasoning'' refer to generation settings. When we say that a reply contains reasoning, we mean that the provider recorded reasoning output for it; with reasoning enabled, some replies have none. Paired runs use the same model identifier and prompts, but reasoning settings, serving software, readout, and retry policy vary across the runs. These comparisons concern the evaluated configurations and do not identify a unique internal mechanism.

\paragraph{Shared evaluation prompts.}
Most configurations in Figure~\ref{fig:llm} are evaluated on the same $7{,}800$ prompts from the first $200$ tasks. These include no-description prompts at $n=1$, $2$, $4$, $\ldots$, $64$, with additional points at $n=40$ and $48$ near the $c=36$ crossing, and every description condition at $n=1$, $2$, and $4$. The gpt-oss-20b and Olmo~3 7B Think \citep{olmo2025three} runs omit the two additional baseline points and contain $7{,}400$ prompts. Results without reasoning for the open-weight models are taken from the $2{,}000$-task run restricted to these tasks. Paired mode comparisons use the same prompts, although serving environments differ as detailed below. At least $99.7\%$ of replies in each run contain a number.

\paragraph{Open-weight reasoning models.}
With reasoning, gpt-oss-20b runs in vLLM using greedy decoding, low reasoning effort, and at most $4{,}096$ new tokens. It reaches the final channel in $99.9\%$ of replies and uses $322$ tokens on average. Qwen3.5 9B runs through OpenRouter at temperature $0$, with reasoning enabled and a limit of $24{,}576$ new tokens. We pin requests to DeepInfra, which serves the model in bf16, because quantization varies across providers. Of its replies, $2{,}305$ repeat themselves until they reach the token limit. Each is rerun once with the model card's recommended reasoning sampling settings: temperature $1.0$, top-$p$ $0.95$, top-$k$ $20$, and presence penalty $1.5$. Eleven remain unfinished and one request fails.

Gemma~4 31B (\texttt{gemma-4-31b-it}) runs through the Gemini API at temperature $0$. Reasoning is enabled by default, and the model uses $2{,}613$ reasoning tokens on average, with the same $24{,}576$-token limit. Of its replies, $435$ reach the limit; all finish after one rerun with the model card's recommended sampling settings: temperature $1.0$, top-$p$ $0.95$, and top-$k$ $64$.

We also run Olmo~3 7B Think (\path{allenai/Olmo-3-7B-Think}), a small open-weight model that always reasons and so has no run without reasoning. It runs in vLLM with greedy decoding and at most $32{,}768$ new tokens. We rerun the $169$ replies that reach this limit once with temperature $0.6$ and top-$p$ $0.95$; $17$ remain unfinished. The model generates $9{,}215$ tokens on average and writes a worked solution before most answers. Its long greedy outputs depend on the hardware: an earlier run of the same conditions on a different GPU gave the same final number on only half the prompts. We report a single run and treat it as one sample from this variation. It averages the demonstrations about as well as the reference but places more weight on the description at $c=1$ and $4$. At $c=36$, its replies split between the prior mean alone and other prediction rules, as detailed below.

\paragraph{Models served through command-line agents.}
GPT-6 Sol (\texttt{gpt-6-sol}, the model identifier served by Codex during the runs) runs through the Codex command-line agent in a read-only sandbox, with an empty configuration directory so that no user instructions or settings load, and with every tool that can run code disabled. We evaluate the model with reasoning disabled (no reasoning tokens) and enabled at low effort, at which, in a pilot, its answers were already within $1$ of the reference's predictions.

Claude Opus~4.6 (\texttt{claude-opus-4-6}) and Haiku~5.5 (\texttt{claude-haiku-5-5}) run through the Claude Code command line, with one prompt per call, no tools, no project or user instructions, and the system prompt ``You are a helpful assistant.'' Opus~4.6 uses high effort in both evaluated modes, with reasoning either enabled or disabled, so that the two runs differ only in reasoning; the disabled mode emits no reasoning tokens. With reasoning enabled, at least $99\%$ of replies in each description condition include reasoning output, with an average of $599$ reasoning tokens across all replies. Without a description, only $1\%$, $24\%$, and $79\%$ of replies include reasoning output at $n=1$, $2$, and $4$, respectively, so its baseline curve at small $n$ mostly reflects replies without reasoning; using the reference's baseline curve instead changes its ESS by at most $1$ (see below). Haiku~5.5 is evaluated mainly at medium effort, because at low effort it often answers without reasoning; we also report low effort for comparison. At low effort and $n=1$, it often repeats the single demonstration value without reasoning output, so its description weight at $n=1$ is low even in conditions whose ESS is close to the reference value. At medium effort and $c=36$, its ESS is $3.4$ at $n=1$, $35$ at $n=2$, matching the reference, and $28$ at $n=4$, against the reference's $33$; its median ESS is therefore $28$, against $34.6$, though its bootstrap interval in Figure~\ref{fig:llm}b includes the reference's value. At $n=1$, $28\%$ of its replies contain no recorded reasoning output, against $19\%$ at $c=1$ and $20\%$ at $c=4$. Both Claude models use the command line's default sampling settings, which the command line does not report, and we collect one reply per prompt. Without reasoning, Opus~4.6 still writes out intermediate steps in $64$ of its $7{,}800$ replies; excluding these replies changes no median ESS by more than $0.1$.

Because hosted models can change over time, we record when each was evaluated. The $2{,}000$-task run took place on 2--3 October 2026, and its conditions in which the stated precision differs from the generating one, and gpt-oss-20b's reasoning run, took place on 20 October. Haiku~5.5 was evaluated on 20 October for the runs of Section~\ref{sec:llm} and 4 November for wording, the stated baseline prior, and the message-sorting experiment. Counted in demonstrations, the shortfall from the reference is much smaller at $c=4$ and $c=1$ than at $c=36$, because the reference's own ESS is small there, but most models still reach less than three fifths of the reference's ESS (Table~\ref{tab:reason}). Most models also respond too little to the stated precision itself. When the prompt states $c=4$ for descriptions generated at $c=36$, the reference's ESS falls from $34.6$ to $13.7$ (Table~\ref{tab:reason}). GPT-6 Sol's ESS falls by a larger fraction than the reference's, and that of Opus~4.6 and Gemma~4 31B by about half, somewhat less than the reference's. The ESS of Qwen3.5 9B and gpt-oss-20b falls by a quarter or less, against three fifths for the reference, so these two models respond little to the stated precision.

Qwen3.5 9B levels off near $11$ from $n=32$ onward ($11.2$ at $n=64$), with up to $11$ replies per cell that far from the sample mean.

For these models, the error with a description sometimes lies below the whole baseline curve, so the evaluated grid contains no crossing. Table~\ref{tab:reason} therefore also reports, in parentheses, a comparison using the reference's baseline. Opus~4.6 and GPT-6 Sol do not exhibit these arithmetic failures. Opus~4.6 has root-mean-square error $7.4$ at $n=64$, matching the reference on these tasks. \subsection{Prediction Rules in Individual Replies}\label{app:rules}

\paragraph{Per-response description weights.}
At $n=4$, we compute the per-response description weight $(\hat w-\bar y)/(m-\bar y)$. This quantity describes one response and differs from the fitted coefficient obtained by regressing predictions across tasks. We use the tasks with $|m-\bar y|\geq30$, where the weight is well determined: $61$ tasks at $c=36$, whose more accurate prior means lie closer to the sample mean, and $124$ at $c=1$. We exclude replies without a number. A reply is classified as consistent with a rule when its per-response weight is within $0.05$ of that rule's weight. The candidate weights are the Bayesian reference ($0.90$ for $c=36$ and $0.20$ for $c=1$); the reference with the description's and the demonstrations' precisions exchanged, $n/(c+n)$ ($0.10$ and $0.80$); the description counted as one additional observation, $1/(n+1)$; the description alone, with weight $1$; and the demonstrations alone, with weight $0$. The one-additional-observation rule coincides with the reference at $c=1$.

With reasoning, Opus~4.6, GPT-6 Sol, Gemma~4 31B, and Haiku~5.5 match the reference rule on $89$ to $100\%$ of eligible replies. Without reasoning, $77\%$ of Opus~4.6 replies at $c=36$ match none of these candidate rules, as do more than half of GPT-6 Sol replies. Enabling reasoning does not ensure agreement with the reference in every model. Olmo~3 7B Think reaches a median ESS of only $6.2$ at $c=36$, although it averages demonstrations well: without a description, its root-mean-square error falls from $56$ at $n=1$ to $10.8$ at $n=32$, compared with $10.0$ for the reference. Its shortfall lies in combining the description with the demonstrations. At $n=1$, it repeats the prior mean in $57$ to $80\%$ of replies, more often at higher stated precision, and at $n=4$, about half of its eligible replies return the prior mean alone and a third match the reference.

\subsection{Stated Reliability}\label{app:llm-reliability}

We test stated reliability in two designs. In both, the prompt adds a sentence, the \emph{warning}, that states a chance that the description is wrong. In the \emph{mixed design} of Section~\ref{sec:llm-stated}, descriptions are irrelevant with the stated probability and the warning states what holds in that case. In the \emph{open-alternative design}, the warning leaves the irrelevant case open, saying only that the mean is then unknown; in the results of Tables~\ref{tab:llm} and~\ref{tab:reason}, every description in this design is relevant; we report it second, because it shows what models do when the prompt does not determine how to update.

\paragraph{Mixed design.}
The prompt adds the sentence ``There is a 10\% chance that this statement is wrong, in which case the mean was instead drawn uniformly at random from the whole numbers 100 to 999,'' or the same sentence with 50\%. For cost reasons, we run this design on the three models that our subscriptions cover, GPT-6 Sol, Opus~4.6, and Haiku~5.5. Each of the $200$ tasks is evaluated with its relevant $c=36$ description and with an irrelevant one, whose mean is drawn independently of the task from the same marginal distribution. With stated chance $1-p$, the error with the description is $p$ times the mean squared error with the relevant description plus $1-p$ times that with the irrelevant one, so that the stated chance is the true one. The stated alternative is the reference's baseline prior, not the distribution that generates the tasks; the prompt states it because without it the posterior relevance probability is not determined. ESS is then computed as in Section~\ref{sec:llm}, against each model's own baseline curve, with intervals that resample tasks. \emph{Fixed-weight averaging} conditions each component on the demonstrations and averages the two posterior means with the prior weights $p$ and $1-p$; a predictor that ignores the warning treats every description as relevant.

Table~\ref{tab:matched} reports the results. At a $10\%$ chance, the reference's median ESS is $5.0$, against $34.6$ without the warning, and the two simpler predictors have ESS $0.3$ and $-0.1$: the description's remaining value depends on recognizing, from the demonstrations, the tasks on which it is irrelevant. At a $50\%$ chance, the reference's ESS is $0.9$, and both simpler predictors do worse with the description than without it. GPT-6 Sol with reasoning is within $0.2$ of the reference at both chances, and about nine in ten of its replies are within $2$ of the reference's prediction with either kind of description. Opus~4.6 with reasoning is within $0.1$ of the reference at both chances, with $96$ to $100\%$ of its replies within $2$ of the reference's prediction. Haiku~5.5 falls short, at a $10\%$ chance mainly with irrelevant descriptions and at $50\%$ with both kinds. Without reasoning, GPT-6 Sol and Opus~4.6 gain little or nothing from the description.

\paragraph{When the prompt leaves the irrelevant case open.}
In the open-alternative design, the warning gave a $10\%$ or $50\%$ chance that the description is ``wrong,'' in which case ``the mean is unknown,'' and the descriptions themselves remained relevant. A stated $50\%$ chance of irrelevance then reduces reference ESS from $34.6$ to $5.7$ under the uniform baseline prior (Table~\ref{tab:reason}). Without reasoning, the ESS of Opus~4.6, gpt-oss-20b, Qwen3.5 9B, and Gemma~4 31B falls by about a third to three fifths, against $84\%$ for the reference, and GPT-6 Sol's falls from $10.3$ to $0.9$.

\paragraph{Fixed-weight averaging.}
The Bayesian reference averages its two component predictions with the posterior relevance probability $\pi_n$, which the demonstrations move away from the stated $p$. For $c=36$, we compare it with fixed-weight averaging, defined above, which keeps the prior weights $p$ and $1-p$. Treating the uniform baseline prior as flat, fixed-weight averaging gives weight $p\,36/(36+n)$ to $m$. Table~\ref{tab:hedge} reports fitted description weights under the open-alternative design's warning, which leaves the baseline prior unspecified. At the stated $50\%$, GPT-6 Sol, Gemma~4 31B, and Qwen3.5 9B with reasoning are close to fixed-weight averaging. Opus~4.6 starts near the reference at $n=1$ but falls below fixed-weight averaging by $n=4$, and Haiku~5.5 at medium effort lies between the two at $n=1$ and $2$. Haiku~5.5 at low effort comes closest to the reference, although its replies often contain no reasoning output at $n=1$. The individual replies show the same pattern. Pooling $n=1$, $2$, and $4$ at the stated $50\%$, the share of replies within $2$ of the fixed-weight prediction is $100\%$ for Gemma~4 31B, $97\%$ for Qwen3.5 9B, $89\%$ for GPT-6 Sol, $80\%$ for Opus~4.6, $58\%$ for Haiku~5.5 at medium effort, and $21\%$ for gpt-oss-20b. \paragraph{Stating the baseline prior.}
Computing $\pi_n$ requires the marginal likelihood of the demonstrations under each component, and hence the baseline prior under irrelevance. The open-alternative design's warning says only that the mean is otherwise ``unknown,'' so the prompt does not determine a unique posterior relevance probability: a model must supply the prior from its pretrained knowledge, and the reference must assume one. The assumption matters: with its baseline curve held fixed, the reference's median ESS at the stated $50\%$ is $5.7$ under our uniform prior over $100$ to $999$, $4.6$ under the generating distribution $\mathcal{N}(500,100^2)$, and $13.4$ under a uniform prior over $0$ to $2000$. To remove this ambiguity, we rerun the stated-reliability condition on the same $200$ tasks, at $c=36$, stated irrelevance probabilities of $10\%$ and $50\%$, and $n=1$, $2$, and $4$. The prompt now states the reference's uniform baseline prior over $100$ to $999$. We use GPT-6 Sol at low effort and Haiku~5.5 at medium effort, with $1{,}200$ prompts each; these runs also supply the relevant-description half of the mixed design above. Opus~4.6, at high effort with reasoning and without it, answers the same prompts, which supply the relevant half of its mixed-design results. Table~\ref{tab:fallback} compares their fitted description weights with those from the open-alternative design.

At the stated $50\%$, the reference and fixed-weight predictions differ by at least $5$ on $123$ to $155$ tasks per cell. On these tasks, when the baseline prior is stated, the share of replies closer to the reference than to the fixed-weight prediction rises from $0$--$5\%$ to $92$--$97\%$ for GPT-6 Sol, and from $21$--$41\%$ to $87$--$95\%$ for Haiku~5.5. At the stated $10\%$, at most $7$ tasks per cell separate the two rules by this amount, so the comparison is uninformative there. Pooling the three values of $n$ at the stated $50\%$, the share of replies within $2$ of the reference prediction rises from $10\%$ to $90\%$ for GPT-6 Sol and from $23\%$ to $58\%$ for Haiku~5.5.

A constant increase in the description weight could also make replies closer to the reference, because its posterior relevance probability exceeds the stated $50\%$ on most tasks. To test whether the weights vary with the evidence, we use each reply's \emph{normalized description weight}: its per-response weight divided by $c/(c+n)$, restricting to tasks with $|m-\bar y|\geq30$. For the scalar reference, this equals its posterior relevance probability $\pi_n$, up to the negligible boundary effects discussed above. For model predictions, the ratio can lie outside $[0,1]$ and does not identify an internal probability. Here $\pi_n$ ranges from $0.08$ to $0.88$ as the demonstrations provide different evidence for relevance; fixed-weight averaging keeps the normalized weight constant.

We regress the models' normalized weights on $\pi_n$, pooling $n=1$, $2$, and $4$ at the stated $50\%$ ($269$ replies per model). With the baseline prior stated, the slopes are $0.96$ [$0.84$, $1.04$] for GPT-6 Sol and $0.98$ [$0.82$, $1.15$] for Haiku~5.5, compared with $0.01$ [$-0.09$, $0.11$] and $0.22$ [$-0.01$, $0.45$] under the open-alternative design's warning. The $95\%$ intervals resample the $153$ tasks. The corresponding intercepts with the prior stated are $0.01$ and $0.03$, and $R^2$ is $0.57$ and $0.33$.

The agreement also holds when the demonstrations count against the description. Among the $23$ replies with $\pi_n$ below $0.5$ (mean $0.33$), the mean normalized weights are $0.30$ and $0.38$ for the two models with the baseline prior stated, compared with $0.48$ and $0.50$ under the open-alternative design's warning. Both models therefore vary their description weights across tasks in approximately the amount predicted by Bayesian model averaging.

Median ESS uses each model's baseline curve from the runs of Section~\ref{sec:reasoning}. At the stated $50\%$, fixed-weight averaging gives $4.4$ and the Bayesian reference gives $5.7$. Stating the baseline prior raises ESS from $4.2$ to $5.4$ for GPT-6 Sol and from $3.8$ to $4.2$ for Haiku~5.5. At the stated $10\%$, it changes from $29.7$ to $25.0$ for GPT-6 Sol and from $32.6$ to $15.1$ for Haiku~5.5, compared with $27.5$ for the reference. The two models' fitted weights agree within $0.01$ in this condition (Table~\ref{tab:fallback}). Haiku's lower ESS therefore does not reflect lower average reliance on the description; it comes from a minority of replies far from the reference, some of which repeat a demonstration value. We also ran two further configurations with the baseline prior stated. Haiku~5.5 at low effort also updates (slope $0.93$), with median ESS $2.7$ at the stated $50\%$, against $5.5$ under the open-alternative design's warning. Opus~4.6 without reasoning does not (slope $-0.18$), with median ESS $3.8$ under both warnings.

\subsection{Wording with Reasoning Enabled}\label{app:wording-reasoning}

Because reasoning brings description weights close to the reference under the original wording, we test whether it does so under the alternative wordings as well. We evaluate the three alternative wordings with Haiku~5.5 at medium effort, for the three relevant descriptions at $n = 1$, $2$, and $4$ on the first $200$ tasks; all $5{,}400$ replies contain a number. With ``An earlier estimate put its mean at $m$, with a standard error of $\tau$'', at least $71\%$ of replies in each cell include reasoning output; $99\%$ of these lie within $2$ of the reference prediction, the tolerance of Table~\ref{tab:matched}. Under ``Its mean is about $m$, give or take $\tau$'' and ``Mean: $m \pm \tau$'', reasoning output is absent from $4$ to $36\%$ and $2$ to $74\%$ of replies per cell, respectively. Even among replies with reasoning output, $71\%$ and $91\%$ repeat the prior mean, and $43\%$ and $32\%$ lie within $2$ of the reference prediction; the two groups overlap, because repeating the prior mean can lie within $2$ of the reference when the description is precise. At $c = 1$ and $n = 4$, its description weights are $0.72$ and $0.93$, compared with reference weight $0.20$.

All wordings provide a value $m$ and a scale $\tau$, but ``give or take'' and ``$\pm$'' do not identify $\tau$ as a prior standard deviation or specify a distribution for the mean. The comparison varies the explicitness of the probabilistic specification as well as its wording. A model that combines a description with demonstrations correctly when the prompt states a distribution therefore need not do so when the prompt does not.

\subsection{Descriptions in Words: Sorting Messages}\label{app:semantic}

The numerical descriptions state a distribution over the task, whereas descriptions in practice usually state constraints in words that the model must interpret. We therefore design a message-sorting experiment with such descriptions that still admits an exact Bayes-optimal predictor. As in Bayesian models of rule-based concept learning \citep{goodman2008}, the hidden task is one of a finite set of rules, here $60$ sorting rules under a uniform prior. A note constrains the rule in words: a broad note leaves $20$ compatible rules, and a specific note leaves $2$. With reasoning, Haiku~5.5 and GPT-6 Sol obtain ESS $9.9$ and $9.5$ for the specific note at $n=2$, compared with $11.4$ for the reference, and when the note may be irrelevant, most of their predictions are closer to the Bayesian reference than to fixed-weight averaging.

\paragraph{Task.}
A message has six binary properties: its sender is outside the organization; it requests a payment; it concerns travel; it requests computer access; it has a deadline within a day; and it contains personal contact information. Each message states every property as present or absent, using one of three phrasings for each value, such as ``I'm a contractor from another company.'' or ``I'm on the sales team here.'' Properties are sampled independently with probability one half, phrasings are sampled uniformly, and sentences appear in random order.

A rule uses exactly two properties and requires each to be present or absent. A message goes into folder A when both requirements hold, and into B otherwise. There are $\binom{6}{2}2^2=60$ such rules. The prompt describes this family, calling the rule the company's filing policy, and states that it was chosen uniformly from the family. It then provides a note, $n$ previously sorted messages with their folders, and four new messages. The model is asked for each new message's probability of going into A, as a number between $0$ and $1$, on four lines from ``1: \textless probability\textgreater'' to ``4: \textless probability\textgreater''.

\paragraph{Notes.}
A broad note reads, for example, ``Policy note: whether it concerns travel is one of the two properties the policy uses,'' leaving $20$ possible rules. A specific note reads ``Policy note: to go into A, a message must request a payment. The other property the policy uses is whether it concerns travel,'' leaving $2$. These notes state constraints in words; the model must determine which rules satisfy them.

The unreliable note is a specific note with an added sentence: ``This note has a 50\% chance of being wrong, in which case it says nothing about the policy, which is then any of the 60, equally likely.'' In the generator, the note is relevant with probability one half and otherwise describes an independently drawn rule. The note is irrelevant in $92$ of the $200$ tasks. An independently drawn note can agree with the actual rule by chance, so we distinguish \emph{relevance}, the latent component that generated the note, from \emph{compatibility}, whether a rule satisfies it.

\paragraph{Reference and ESS.}
For a note asserted to be relevant, the reference predicts the fraction of rules consistent with the note and the sorted messages that assign the new message to A. For an unreliable note, it averages this prediction with the prediction from rules consistent with the sorted messages alone, weighting the two by the posterior relevance probability. The prior relevance probability is $0.5$; the posterior probability is obtained using the likelihood of the demonstrations under each component. As a check on our implementation, on $3{,}000$ simulated tasks the reference's predictive probabilities are calibrated in every condition, and its posterior probability that the unreliable note is relevant matches the frequency of relevance: where it exceeds $0.7$, it averages $0.80$, and the note is relevant in $80\%$ of cases.

The loss is the Brier score, the squared error between the predicted probability of A and the true folder indicator, averaged over the four query messages. Without demonstrations, a broad note leaves the prediction unchanged: for any message, exactly a quarter of the $20$ rules compatible with the note send it to A, the same fraction as among all $60$, so the broad note's ESS at $n=0$ is zero. ESS follows Definition~\ref{def:ess}, using each learner's baseline curve, its loss without a note, at $n=0$, $2$, $4$, $6$, $8$, $12$, $16$, $20$, $24$, and $32$, with linear interpolation in $n$. On simulated tasks, this grid changes the reference ESS by at most $0.6$ relative to evaluation at every integer demonstration count.

\paragraph{Runs.}
We use $200$ tasks, each defined by a sampled rule, and $19$ conditions: no note at the ten demonstration counts above, and each note at $n=0$, $2$, and $4$. This gives $3{,}800$ prompts per configuration. Haiku~5.5 runs at medium effort; GPT-6 Sol runs without reasoning and at low effort. We leave out Opus~4.6, because in a pilot it still wrote out its working on this task with reasoning disabled, so its two settings would not differ only in reasoning. The command-line agents are set up as in Appendix~\ref{app:reasoning-runs}, with no tools, and no reply calls a tool. To check that GPT-6 Sol without reasoning reads the messages correctly, we asked it to state each property of $96$ messages; it was correct in $97$ to $100\%$ of cases for each property; all three errors concern one phrasing, ``I'm not traveling for this.'' Fourteen replies from GPT-6 Sol at low effort contain no probability and are excluded; one Haiku~5.5 reply omits one of its four probabilities, and we score its other three. Every Haiku~5.5 reply includes reasoning output, with a median of $3{,}008$ reasoning tokens. For GPT-6 Sol at low effort, $91\%$ of replies include reasoning output, with a median of $142$ reasoning tokens.

\paragraph{Results.}
Table~\ref{tab:semantic} reports each note's ESS. With reasoning, both models are within $2$ demonstrations of the reference in every condition except GPT-6 Sol's specific note at $n=4$: its ESS is $26.1$, compared with $14.8$ for the reference. Its loss with this note, $0.008$, is close to the reference's $0.007$, but its baseline curve flattens beyond $n=16$, with loss $0.022$ at $n=20$, compared with $0.004$ for the reference. It consequently needs more demonstrations on its own baseline curve to match the note's error reduction.

For the unreliable note, we compare predictions with the Bayesian reference and with fixed-weight averaging, which averages the two component predictions using their prior weights. Here it retains the stated $50\%$ weight unless the sorted messages rule out every rule compatible with the note; in that case, it assigns zero weight to the relevant component. We use query messages on which the two predictions differ by at least $0.05$: about $150$ at $n=2$ and $200$ at $n=4$, out of $800$. The share of predictions closer to the reference is $90\%$ at $n=2$ and $99\%$ at $n=4$ for Haiku~5.5; $77\%$ and $87\%$ for GPT-6 Sol at low effort; and $45\%$ at both counts for GPT-6 Sol without reasoning.

Without reasoning, GPT-6 Sol learns slowly from demonstrations. Its loss without a note is still $0.078$ at $n=32$, compared with less than $0.0005$ for the reference. Measured against this weaker baseline, a note can have an ESS as large as the reference's or larger. For example, the specific note has ESS $13.5$ at $n=2$, although the model's loss with that note is $0.130$, compared with $0.027$ for the reference. This illustrates why learner-specific ESS must be interpreted alongside absolute prediction error.

\section{Additional Related Work}\label{app:related}

\paragraph{Task descriptions and demonstrations.}
\citet{weller2020} formalize learning from task descriptions by distinguishing the latent task, its natural-language description, and individual input--output examples. We use \emph{task description} for information about the task supplied in the prompt, including a numeric description token in the meta-trained setting and probabilistic statements or notes about a sorting rule in the language-model experiments. A \emph{demonstration} is an observed input--output example; in scalar mean estimation, it is an observation at the fixed input $x=1$. Summaries distilled from demonstrations can serve as descriptions \citep{honda2025}; our controlled experiments instead specify the joint distribution of task, description, and demonstrations.

\paragraph{Prior information and unreliable descriptions.}
The two-component construction has the form of the robust mixture priors of Bayesian clinical trials, which combine informative and baseline distributions and update their component weights after observing data \citep{schmidli2014}. Our mixture is specified directly, rather than derived from a historical-data meta-analysis. Reliability $p$ is the prior probability of the relevant component; $\pi_n$ is its posterior probability. Averaging component predictions using $\pi_n$ is Bayesian model averaging \citep{hoeting1999}. In a robust mixture prior, the prior weight is fixed but the posterior weights still update; fixed-weight averaging, our experimental comparison, omits this update.

In our model, an irrelevant description is independent of the task and may happen to agree with it. Irrelevance is therefore a property of how the description was generated, whereas prior--data conflict concerns disagreement between prior information and observed data.

\paragraph{Specificity and description weights.}
Specificity takes a concrete form in each setting. Section~\ref{sec:setting} measures it by what a relevant description leaves unknown about the task: the smallest expected loss of a prediction made from the description's prior alone, which \citet{grunwald2004} call the generalized entropy of that prior under the loss. Under squared error this is the prior's variance, which in the Gaussian model is $\tau^2$ in each direction that the description constrains; a partial description constrains $k$ of them. A message-sorting note leaves a uniform prior over the rules compatible with it, and we describe its specificity by their number, $20$ for a broad note and $2$ for a specific one; the logarithm of that number is the prior's entropy, the corresponding measure under log loss. These quantities do not share a scale across tasks; ESS expresses each in demonstrations. Our description weights follow Gaussian mean estimation, in which the posterior combines the prior mean and the sample mean with weights proportional to their precisions \citep{neuenschwander2020}. Fitted and per-response weights summarize model predictions; their normalized values can be compared with posterior component probabilities but need not be probabilities.

\paragraph{Effective sample size and predictive comparisons.}
Prior ESS has several definitions, including matching local information \citep{morita2008}, matching expected posterior loss \citep{reimherr2021}, and quantifying sample savings at a target estimation accuracy \citep{wiesenfarth2020}. Matching information requires an explicit prior. A network or a language model has prior knowledge from training, but only implicitly, in its parameters; its prediction error, by contrast, can be measured with and without the description. Our definition therefore follows the error-matching approach, but it evaluates population prediction error, allows a non-Bayesian learner, and depends on the demonstration count. A learner without a description still has prior knowledge, from the baseline prior or from training, and ESS measures what the description adds to it, so we measure ESS against each learner's own baseline curve. For a learner whose baseline curve falls slowly, the same error reduction is worth more demonstrations, so a large ESS need not imply low absolute error (Table~\ref{tab:error}). A negative ESS means that the description raises error. The word \emph{predictive} specifies what is matched; it does not assert the additive predictive-consistency property studied by \citet{neuenschwander2020}.

Two predictive comparisons are especially close. \citet{lescao2021} average horizontal data advantages over an accuracy range in prompt-based fine-tuning; we evaluate a pointwise difference in demonstration counts. \citet{selby2025} compare priors elicited from language models with data-based predictors by the observations needed to match predictive loss; we study descriptions supplied to a learner and how their benefit changes after demonstrations. Other work compares instructions or prompts with examples. Beyond ICL, an instruction can replace up to $100$ execution examples in the fine-tuning settings studied by \citet{cook2026}, and \citet{wenliang2026} compare optimized prompts with demonstrations in terms of their length and effect.

\paragraph{Demonstrations, text, and probabilistic prediction.}
Other work examines semantic priors and flipped labels \citep{wei2023}, weak dependence on demonstration labels \citep{min2022}, Bayesian scaling laws \citep{arora2025}, and Bayesian reference curves for in-context function learning \citep{akata2026}. Text supplied alongside numbers can change numerical predictions \citep{requeima2024}. Language-model ICL can violate the martingale property that Bayesian prediction implies \citep{falck2024}, and \citet{tong2026} study how sensitivity to the prompt template varies with the number of demonstrations. Related work studies how language-model outputs compare with Bayesian inference and how training can improve probabilistic reasoning \citep{qiu2026}; \citet{he2025} examine Bayesian consistency during iterative reasoning on open-ended questions. Our numerical experiments state uncertainty explicitly, allowing comparison with a specified Bayesian reference as precision and relevance probability vary. The message-sorting experiment extends this comparison to constraints stated in words on a finite family of classification rules.

\paragraph{Scope of the results.}
The $d+1$ term of Proposition~\ref{prop:reliable} arises from random regression inputs; it is absent when every input is the same, as in our mean-estimation task (Appendix~\ref{app:ess-est}). For language models, the revision of a stated chance of irrelevance carries over to a description that states a rule in words (Appendix~\ref{app:semantic}). Agreement with the reference does not carry over to informal wording: when the prompt gives the prior mean ``give or take'' an amount, most of Haiku~5.5's replies with reasoning repeat the prior mean (Appendix~\ref{app:wording-reasoning}).
